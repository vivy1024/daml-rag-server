# 日志查询和分析仪表板使用指南

**版本**: v1.0.0  
**创建日期**: 2025-12-23  
**仪表板文件**: `logs-query-analysis.json`

---

## 概述

日志查询和分析仪表板提供了全面的日志查询、分析和可视化功能，帮助运维工程师和开发人员快速定位问题、分析系统行为和监控系统健康状态。

---

## 面板说明

### 1. 实时日志流

**位置**: 顶部，全宽  
**功能**: 显示最新的100条日志，每10秒自动刷新  
**特点**:
- 实时更新，无需手动刷新
- 可以点击日志中的 `request_id`、`user_id`、`session_id` 等字段，自动跳转到相关日志查询
- 支持日志详情展开，查看完整的日志内容

**使用场景**:
- 实时监控系统运行状态
- 快速查看最新的系统活动
- 发现异常时立即查看日志

---

### 2. 错误日志

**位置**: 左侧，第二行  
**功能**: 只显示 ERROR 和 CRITICAL 级别的日志  
**特点**:
- 过滤掉正常日志，聚焦于错误
- 最多显示50条错误日志
- 按时间倒序排列

**使用场景**:
- 快速定位系统错误
- 分析错误发生的频率和模式
- 错误排查和问题诊断

---

### 3. 请求追踪（按Request ID）

**位置**: 右侧，第二行  
**功能**: 根据 `request_id` 查看该请求的完整日志链路  
**特点**:
- 按时间正序排列，展示请求的完整生命周期
- 最多显示200条日志
- 可以看到请求从开始到结束的所有步骤

**使用方法**:
1. 在仪表板顶部的 "Request ID" 输入框中输入 request_id
2. 面板会自动更新，显示该请求的所有日志
3. 按时间顺序查看请求的执行过程

**使用场景**:
- 追踪特定请求的完整执行过程
- 分析请求失败的原因
- 性能分析：查看各步骤的耗时

---

### 4. 日志级别统计（每分钟）

**位置**: 左侧，第三行  
**功能**: 按日志级别统计每分钟的日志数量  
**特点**:
- 堆叠面积图，直观显示各级别日志的占比
- 颜色编码：ERROR(红色)、CRITICAL(深红)、WARNING(橙色)、INFO(蓝色)
- 可以快速识别日志量的异常波动

**使用场景**:
- 监控系统日志量的变化趋势
- 识别日志量异常增长的时间点
- 分析不同日志级别的分布

---

### 5. 错误日志数量趋势

**位置**: 右侧，第三行  
**功能**: 显示 ERROR 和 CRITICAL 日志的数量趋势  
**特点**:
- 平滑曲线，易于观察趋势
- 显示平均值和最大值
- 阈值告警：超过10个错误时变红

**使用场景**:
- 监控错误发生的频率
- 识别错误高峰期
- 评估系统稳定性

---

### 6. 慢请求日志（耗时>3秒）

**位置**: 全宽，第四行  
**功能**: 显示总耗时超过3秒的慢请求日志  
**特点**:
- 自动过滤出慢请求
- 最多显示50条
- 可以看到请求的完整信息和耗时

**使用场景**:
- 识别性能瓶颈
- 分析慢请求的原因
- 性能优化的依据

---

### 7. 步骤日志（按步骤筛选）

**位置**: 左侧，第五行  
**功能**: 按工作流步骤筛选日志  
**特点**:
- 下拉菜单选择步骤（步骤1-步骤11）
- 只显示选中步骤的日志
- 最多显示100条

**使用方法**:
1. 在仪表板顶部的 "步骤名称" 下拉菜单中选择步骤
2. 面板会自动更新，显示该步骤的所有日志

**使用场景**:
- 分析特定步骤的执行情况
- 排查某个步骤的问题
- 了解步骤的执行频率

---

### 8. 用户请求日志（按User ID）

**位置**: 右侧，第五行  
**功能**: 查看特定用户的所有请求日志  
**特点**:
- 输入 user_id 即可查询
- 最多显示100条
- 按时间倒序排列

**使用方法**:
1. 在仪表板顶部的 "User ID" 输入框中输入 user_id
2. 面板会自动更新，显示该用户的所有请求日志

**使用场景**:
- 追踪特定用户的行为
- 排查用户报告的问题
- 分析用户的使用模式

---

### 9-12. 统计面板

**位置**: 底部，四个并排的统计卡片  
**功能**: 显示关键指标的统计数据

#### 9. 日志总量统计
- 显示当前时间范围内的日志总数
- 绿色显示

#### 10. 错误日志数量
- 显示当前时间范围内的 ERROR 日志数量
- 颜色阈值：<10(绿色)、10-50(黄色)、>50(红色)

#### 11. 慢请求数量
- 显示当前时间范围内耗时超过3秒的请求数量
- 颜色阈值：<5(绿色)、5-20(黄色)、>20(红色)

#### 12. 平均请求耗时
- 显示当前时间范围内的平均请求耗时
- 单位：毫秒
- 颜色阈值：<2000ms(绿色)、2000-5000ms(黄色)、>5000ms(红色)

**使用场景**:
- 快速了解系统整体状态
- 监控关键性能指标
- 识别异常情况

---

## 变量说明

仪表板顶部有三个变量输入框，用于动态筛选日志：

### 1. Request ID
- **类型**: 文本输入框
- **用途**: 输入 request_id 查看该请求的完整日志链路
- **示例**: `req_abc123`

### 2. User ID
- **类型**: 文本输入框
- **用途**: 输入 user_id 查看该用户的所有请求
- **示例**: `1`

### 3. 步骤名称
- **类型**: 下拉菜单
- **用途**: 选择工作流步骤查看该步骤的日志
- **选项**: 步骤1, 步骤2, ..., 步骤11

## 使用技巧

### 1. 时间范围选择

仪表板右上角可以选择时间范围：
- **快速选择**: Last 5 minutes, Last 15 minutes, Last 1 hour, Last 6 hours, Last 24 hours
- **自定义**: 点击时间范围可以自定义开始和结束时间
- **刷新间隔**: 默认10秒自动刷新，可以调整为5s、30s、1m等

### 2. 日志详情查看

点击任何日志条目可以展开查看详细信息：
- 完整的日志消息
- 所有的标签（labels）
- 可以复制日志内容
- 可以点击字段值进行过滤

### 3. 字段链接

日志中的某些字段（如 request_id、user_id、session_id）是可点击的链接：
- 点击后会自动跳转到相关日志查询
- 无需手动输入变量值

### 4. 面板缩放

- 点击面板标题右侧的图标可以全屏显示该面板
- 按 ESC 键退出全屏

### 5. 导出数据

- 点击面板标题右侧的菜单（三个点）
- 选择 "Inspect" -> "Data" 可以查看原始数据
- 选择 "Export" 可以导出数据为 CSV 或 JSON

## 常见查询场景

### 场景1: 追踪失败请求的完整链路

1. 在 "错误日志" 面板中找到失败的请求
2. 点击日志中的 `request_id` 字段
3. 自动跳转到 "请求追踪" 面板，显示该请求的完整日志链路
4. 按时间顺序查看请求的执行过程，找出失败的步骤

### 场景2: 查询特定时间段的错误日志

1. 在右上角选择时间范围（如：Last 1 hour）
2. 查看 "错误日志" 面板
3. 如果需要更精确的时间，点击时间范围自定义开始和结束时间

### 场景3: 分析慢请求的性能瓶颈

1. 查看 "慢请求日志" 面板，找到耗时较长的请求
2. 点击日志中的 `request_id` 字段
3. 在 "请求追踪" 面板中查看该请求的完整执行过程
4. 分析各步骤的耗时，找出性能瓶颈

### 场景4: 统计各步骤的平均耗时

1. 在 "步骤名称" 下拉菜单中选择步骤（如：步骤7）
2. 查看 "步骤日志" 面板
3. 观察该步骤的执行频率和日志内容
4. 结合 "平均请求耗时" 统计面板分析性能

### 场景5: 查询特定用户的所有请求

1. 在 "User ID" 输入框中输入用户ID（如：1）
2. 查看 "用户请求日志" 面板
3. 可以看到该用户的所有请求历史
4. 点击 request_id 查看具体请求的详细日志

## LogQL查询示例

仪表板使用的 LogQL 查询语句可以作为参考：

### 1. 查询所有日志
```logql
{job="daml-rag"}
```

### 2. 查询错误日志
```logql
{job="daml-rag"} |= "ERROR" or {job="daml-rag"} |= "CRITICAL"
```

### 3. 查询特定request_id的日志
```logql
{job="daml-rag"} |= "req_abc123"
```

### 4. 查询慢请求（耗时>3秒）
```logql
{job="daml-rag"} |= "total_duration" | json | total_duration_ms > 3000
```

### 5. 统计每分钟的日志数量
```logql
sum by (level) (count_over_time({job="daml-rag"} | json | __error__="" [1m]))
```

### 6. 查询特定步骤的日志
```logql
{job="daml-rag"} |= "步骤7"
```

### 7. 查询特定用户的日志
```logql
{job="daml-rag"} |= "user_id=1"
```

## 故障排查

### 问题1: 面板显示 "No data"

**可能原因**:
- Loki服务未启动
- Promtail未采集到日志
- 时间范围内没有日志数据

**解决方法**:
1. 检查 Loki 服务状态：`docker ps | grep loki`
2. 检查 Promtail 服务状态：`docker ps | grep promtail`
3. 调整时间范围，扩大查询范围
4. 在 Grafana Explore 中手动执行查询验证

### 问题2: 日志显示不完整

**可能原因**:
- 日志采集延迟
- 日志被截断

**解决方法**:
1. 等待几秒钟，日志采集有5秒左右的延迟
2. 点击日志条目展开查看完整内容
3. 调整面板的 `maxLines` 参数增加显示数量

### 问题3: 变量输入不生效

**可能原因**:
- 变量值格式不正确
- 日志中没有匹配的内容

**解决方法**:
1. 确认变量值格式正确（如 request_id 格式）
2. 在实时日志流中查看实际的字段值
3. 尝试使用部分匹配而不是完全匹配

## 性能优化建议

1. **限制时间范围**: 查询大量日志时，缩小时间范围可以提高查询速度
2. **使用标签过滤**: 优先使用标签过滤（如 `{job="daml-rag"}`），而不是文本搜索
3. **合理设置刷新间隔**: 如果不需要实时监控，可以将刷新间隔设置为30s或1m
4. **减少面板数量**: 如果性能不足，可以暂时隐藏不需要的面板
