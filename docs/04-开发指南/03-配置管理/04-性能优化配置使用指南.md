## 概述

本文档专注于 `config/performance_optimization.yaml` 配置文件的详细说明，包括配置结构、参数说明、环境特定配置和配置验证方法。

**注意**: 本文档仅说明配置参数，不包含使用示例和故障排查。如需了解性能优化的使用方法和最佳实践，请参考 [性能优化完整指南](./02-性能优化完整指南.md)。

## 配置文件位置

```
daml-rag-server/config/performance_optimization.yaml
```

**配置加载方式**:
```python
import yaml
from pathlib import Path

config_path = Path("config/performance_optimization.yaml")
with open(config_path, 'r', encoding='utf-8') as f:
    config = yaml.safe_load(f)
```

## 配置结构

配置文件包含以下主要部分：

1. **cache**: 缓存配置
2. **connection_pool**: 连接池配置
3. **llm_fallback**: LLM降级配置
4. **concurrency**: 并发限流配置
5. **monitoring**: 监控配置
6. **bge_classification**: BGE分类配置
7. **workflow**: 工作流超时配置
8. **performance_targets**: 性能目标配置
9. **environments**: 环境特定配置

---

## 1. 缓存配置 (cache)

控制多层缓存系统的行为。

**配置参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `l1_enabled` | boolean | true | 启用L1内存缓存 |
| `l1_max_size` | integer | 1000 | L1缓存最大条目数 |
| `l1_max_memory_mb` | integer | 100 | L1缓存最大内存占用(MB) |
| `l2_enabled` | boolean | true | 启用L2 Redis缓存 |
| `l2_host` | string | "localhost" | Redis主机地址 |
| `l2_port` | integer | 6379 | Redis端口 |
| `l2_db` | integer | 0 | Redis数据库编号 |
| `default_ttl` | integer | 300 | 默认TTL（秒） |
| `ttl_by_type` | object | - | 不同数据类型的TTL配置 |
| `warmup_enabled` | boolean | true | 启用缓存预热 |
| `warmup_batch_size` | integer | 10 | 预热批次大小 |

**TTL配置示例**：
```yaml
ttl_by_type:
  user_profile: 300        # 用户档案：5分钟
  user_membership: 600     # 会员信息：10分钟
  tdee_calculation: 1800   # TDEE计算：30分钟
  exercise_selection: 600  # 动作选择：10分钟
  safety_check: 300        # 安全检查：5分钟
```

**参数调优建议**：

| 数据类型 | 推荐TTL | 缓存级别 | 说明 |
|---------|---------|---------|------|
| 用户档案 | 300-600秒 | L2 Redis | 变化不频繁 |
| 会员信息 | 600-1800秒 | L2 Redis | 可能变化 |
| 临时计算 | 300秒 | L1 Memory | 短期有效 |
| 静态数据 | 7200秒 | L2 Redis | 很少变化 |

## 2. 连接池配置 (connection_pool)

管理MySQL、Neo4j和HTTP连接池。

**配置参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `min_size` | integer | 10 | 最小连接数 |
| `max_size` | integer | 50 | 最大连接数 |
| `max_idle_time` | integer | 60 | 最大空闲时间（秒） |
| `acquire_timeout` | integer | 2 | 获取连接超时（秒） |
| `health_check_interval` | integer | 60 | 健康检查间隔（秒） |

**MySQL连接池配置**：
```yaml
connection_pool:
  mysql:
    min_size: 10
    max_size: 50
    max_idle_time: 60
    acquire_timeout: 2
    health_check_interval: 60
```

**Neo4j连接池配置**：
```yaml
connection_pool:
  neo4j:
    min_size: 5
    max_size: 20
    max_idle_time: 60
    acquire_timeout: 2
    health_check_interval: 60
```

**HTTP连接池配置**：
```yaml
connection_pool:
  http:
    min_size: 20
    max_size: 100
    max_idle_time: 30
    acquire_timeout: 2
    health_check_interval: 60
```

**参数调优建议**：

| 负载类型 | min_size | max_size | 说明 |
|---------|----------|----------|------|
| 低负载 | 5-10 | 20-30 | 小型应用 |
| 中负载 | 10-20 | 50-100 | 中型应用 |
| 高负载 | 20-50 | 100-200 | 大型应用 |

## 3. LLM降级配置 (llm_fallback)

配置LLM调用的降级策略。

**配置参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `primary_backend` | string | "deepseek" | 主要LLM后端 |
| `fallback_backends` | array | ["anthropic-claude", "template"] | 降级后端列表 |
| `max_retries` | integer | 3 | 最大重试次数 |
| `timeout` | integer | 30 | 超时时间（秒） |
| `streaming.interrupt_recovery` | boolean | true | 流式中断恢复 |
| `streaming.buffer_size` | integer | 1024 | 缓冲区大小 |

**降级顺序**：
```
DeepSeek API → Anthropic Claude本地模型 → 模板响应
```

**完整配置示例**：
```yaml
llm_fallback:
  primary_backend: "deepseek"
  fallback_backends:
    - "anthropic-claude"
    - "template"
  max_retries: 3
  timeout: 30
  streaming:
    interrupt_recovery: true
    buffer_size: 1024
```

**参数调优建议**：

| 场景 | max_retries | timeout | 说明 |
|------|-------------|---------|------|
| 稳定网络 | 3 | 30秒 | 默认配置 |
| 不稳定网络 | 5 | 60秒 | 增加容错 |
| 快速响应 | 1 | 15秒 | 降低延迟 |

## 4. 并发限流配置 (concurrency)

控制系统并发请求数量。

**配置参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `max_concurrent` | integer | 100 | 全局最大并发数 |
| `max_queue_size` | integer | 200 | 队列大小 |
| `timeout` | integer | 30 | 超时时间（秒） |
| `user_limits` | object | - | 用户分级限流配置 |

**用户分级限流配置**：

| 用户类型 | max_concurrent | max_queue_size | timeout |
|---------|----------------|----------------|---------|
| free | 10 | 20 | 30秒 |
| paid | 50 | 100 | 60秒 |
| vip | 100 | 200 | 120秒 |
| system | 200 | 400 | 300秒 |

**完整配置示例**：
```yaml
concurrency:
  max_concurrent: 100
  max_queue_size: 200
  timeout: 30
  user_limits:
    free:
      max_concurrent: 10
      max_queue_size: 20
      timeout: 30
    paid:
      max_concurrent: 50
      max_queue_size: 100
      timeout: 60
    vip:
      max_concurrent: 100
      max_queue_size: 200
      timeout: 120
    system:
      max_concurrent: 200
      max_queue_size: 400
      timeout: 300
```

**参数调优建议**：

| 场景 | max_concurrent | max_queue_size | 说明 |
|------|----------------|----------------|------|
| 系统过载 | 50 | 100 | 降低并发 |
| 正常负载 | 100 | 200 | 默认配置 |
| 高吞吐量 | 200 | 400 | 提升并发 |

## 5. 监控配置 (monitoring)

配置性能监控和告警。

**配置参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enabled` | boolean | true | 启用监控 |
| `prometheus.enabled` | boolean | true | 启用Prometheus |
| `prometheus.port` | integer | 9090 | Prometheus端口 |
| `alerts.performance_bottleneck.threshold_ms` | integer | 1000 | 性能瓶颈阈值（毫秒） |
| `alerts.error_rate.threshold` | float | 0.05 | 错误率阈值（5%） |
| `alerts.resource_usage.cpu_threshold` | float | 0.7 | CPU使用率阈值（70%） |
| `alerts.resource_usage.memory_threshold` | float | 0.8 | 内存使用率阈值（80%） |
| `logging.level` | string | "INFO" | 日志级别 |

**告警类型配置**：

1. **性能瓶颈告警**：
```yaml
alerts:
  performance_bottleneck:
    threshold_ms: 1000  # 超过1秒触发告警
    enabled: true
```

2. **错误率告警**：
```yaml
alerts:
  error_rate:
    threshold: 0.05  # 错误率超过5%触发告警
    enabled: true
```

3. **资源使用告警**：
```yaml
alerts:
  resource_usage:
    cpu_threshold: 0.7    # CPU使用率超过70%
    memory_threshold: 0.8  # 内存使用率超过80%
    enabled: true
```

4. **并发超限告警**：
```yaml
alerts:
  concurrency_limit:
    enabled: true
```

**完整配置示例**：
```yaml
monitoring:
  enabled: true
  prometheus:
    enabled: true
    port: 9090
  alerts:
    performance_bottleneck:
      threshold_ms: 1000
      enabled: true
    error_rate:
      threshold: 0.05
      enabled: true
    resource_usage:
      cpu_threshold: 0.7
      memory_threshold: 0.8
      enabled: true
    concurrency_limit:
      enabled: true
  logging:
    level: "INFO"
```

## 7. 工作流超时配置 (workflow)

配置工作流各步骤的超时时间。

**配置参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `global_timeout` | integer | 30 | 全局超时（秒） |
| `step_timeouts` | object | - | 各步骤超时配置 |

**步骤超时配置**：

| 步骤 | 参数名 | 默认值 | 说明 |
|-----|--------|--------|------|
| 步骤1 | `step_1_user_profile` | 0.5秒 | 用户档案加载 |
| 步骤2 | `step_2_session` | 0.3秒 | 会话记录存储 |
| 步骤3 | `step_3_membership` | 0.3秒 | 会员权限检查 |
| 步骤4 | `step_4_bge_classification` | 0.5秒 | BGE分类 |
| 步骤5 | `step_5_model_selection` | 0.2秒 | 模型选择 |
| 步骤6 | `step_6_few_shot` | 1.0秒 | Few-Shot检索 |
| 步骤6.5 | `step_6_5_dag_selection` | 2.0秒 | DAG方案选择 |
| 步骤7 | `step_7_dag_orchestration` | 10.0秒 | DAG编排 |
| 步骤8 | `step_8_retrieval` | 2.0秒 | 三层检索 |
| 步骤9 | `step_9_tool_summary` | 1.0秒 | 工具结果汇总 |
| 步骤10 | `step_10_llm_analysis` | 20.0秒 | LLM分析 |
| 步骤11 | `step_11_record` | 0.5秒 | 记录交互 |

**完整配置示例**：
```yaml
workflow:
  global_timeout: 30
  step_timeouts:
    step_1_user_profile: 0.5
    step_2_session: 0.3
    step_3_membership: 0.3
    step_4_bge_classification: 0.5
    step_5_model_selection: 0.2
    step_6_few_shot: 1.0
    step_6_5_dag_selection: 2.0
    step_7_dag_orchestration: 10.0
    step_8_retrieval: 2.0
    step_9_tool_summary: 1.0
    step_10_llm_analysis: 20.0
    step_11_record: 0.5
```

**参数调优建议**：

| 场景 | global_timeout | step_10_llm_analysis | 说明 |
|------|----------------|----------------------|------|
| 快速响应 | 20秒 | 10秒 | 降低延迟 |
| 标准配置 | 30秒 | 20秒 | 默认配置 |
| 复杂查询 | 60秒 | 40秒 | 支持长时间处理 |

**配置参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `workflow_total_time` | integer | 30 | 工作流总耗时目标（秒） |
| `ttfb` | integer | 5 | 首字节时间目标（秒） |
| `cache_hit_rate` | float | 0.8 | 缓存命中率目标（80%） |
| `qps` | integer | 200 | 每秒查询数目标 |
| `error_rate` | float | 0.01 | 错误率目标（1%） |
| `p95_latency` | integer | 10 | P95延迟目标（秒） |
| `p99_latency` | integer | 20 | P99延迟目标（秒） |

**完整配置示例**：
```yaml
performance_targets:
  workflow_total_time: 30
  ttfb: 5
  cache_hit_rate: 0.8
  qps: 200
  error_rate: 0.01
  p95_latency: 10
  p99_latency: 20
```

**性能目标说明**：

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 工作流总耗时 | <30秒 | 从请求到响应完成的总时间 |
| TTFB | <5秒 | 首字节时间，用户感知的响应速度 |
| 缓存命中率 | >80% | 缓存有效性指标 |
| QPS | 200 | 系统吞吐量指标 |
| 错误率 | <1% | 系统可靠性指标 |
| P95延迟 | <10秒 | 95%的请求响应时间 |
| P99延迟 | <20秒 | 99%的请求响应时间 |

## 9. 环境特定配置 (environments)

配置文件支持不同环境的配置。

**配置参数**：

| 环境 | 说明 | 主要差异 |
|------|------|---------|
| development | 开发环境 | 不使用Redis，不启用Prometheus |
| testing | 测试环境 | 使用Redis，启用Prometheus |
| production | 生产环境 | 完整配置，高并发 |

**开发环境配置**：
```yaml
environments:
  development:
    cache:
      l2_enabled: false  # 不使用Redis
    monitoring:
      prometheus:
        enabled: false   # 不启用Prometheus
    concurrency:
      max_concurrent: 10  # 低并发
```

**测试环境配置**：
```yaml
environments:
  testing:
    cache:
      l2_enabled: true   # 使用Redis
    monitoring:
      prometheus:
        enabled: true    # 启用Prometheus
    concurrency:
      max_concurrent: 50  # 中等并发
```

**生产环境配置**：
```yaml
environments:
  production:
    cache:
      l2_enabled: true   # 使用Redis
      warmup_enabled: true  # 启用预热
    monitoring:
      prometheus:
        enabled: true    # 启用Prometheus
      alerts:
        enabled: true    # 启用告警
    concurrency:
      max_concurrent: 100  # 高并发
```

**环境配置加载方法**：
```python
import yaml
from os import getenv

# 加载配置
with open('config/performance_optimization.yaml') as f:
    config = yaml.safe_load(f)

# 获取环境特定配置
env = getenv('ENVIRONMENT', 'development')
env_config = config['environments'][env]

# 合并环境配置到主配置
for key, value in env_config.items():
    if isinstance(value, dict):
        config[key].update(value)
    else:
        config[key] = value
```

## 10. 配置加载和验证

### 10.1 配置加载器

```python
import yaml
from pathlib import Path

class PerformanceConfig:
    """性能优化配置加载器"""
    
    def __init__(self, config_path: str = "config/performance_optimization.yaml"):
        self.config_path = Path(config_path)
        self.config = self._load_config()
    
    def _load_config(self) -> dict:
        """加载配置文件"""
        with open(self.config_path, 'r', encoding='utf-8') as f:
            return yaml.safe_load(f)
    
    def get_cache_config(self) -> dict:
        """获取缓存配置"""
        return self.config['cache']
    
    def get_connection_pool_config(self, pool_name: str) -> dict:
        """获取连接池配置"""
        return self.config['connection_pool'][pool_name]
    
    def get_llm_fallback_config(self) -> dict:
        """获取LLM降级配置"""
        return self.config['llm_fallback']
    
    def get_concurrency_config(self) -> dict:
        """获取并发限流配置"""
        return self.config['concurrency']
    
    def get_monitoring_config(self) -> dict:
        """获取监控配置"""
        return self.config['monitoring']

# 使用示例
config = PerformanceConfig()
cache_config = config.get_cache_config()
print(f"L1缓存启用: {cache_config['l1_enabled']}")
print(f"L2缓存启用: {cache_config['l2_enabled']}")
```

### 10.2 配置验证脚本

```python
import yaml
from pathlib import Path

def validate_config(config_path: str) -> bool:
    """验证配置文件"""
    try:
        with open(config_path, 'r', encoding='utf-8') as f:
            config = yaml.safe_load(f)
        
        # 验证必需的配置项
        required_sections = [
            'cache', 'connection_pool', 'llm_fallback',
            'concurrency', 'monitoring'
        ]
        
        for section in required_sections:
            if section not in config:
                print(f"❌ 缺少配置节: {section}")
                return False
        
        print("✅ 配置文件验证通过")
        return True
        
    except Exception as e:
        print(f"❌ 配置文件验证失败: {e}")
        return False

# 验证配置
validate_config("config/performance_optimization.yaml")
```
