## 📋 概述

本指南介绍如何使用DAML-RAG框架的三层检索引擎（TrueThreeLayerEngine），这是系统的核心检索组件，确保100%基于真实数据、无幻觉的检索结果。

### 什么是三层检索？

三层检索是DAML-RAG框架的核心技术，通过三个层级的逐步过滤和验证，确保检索结果的准确性和安全性：

```
用户查询
  ↓
Layer 1: 向量语义检索（Qdrant + GTE-Large-zh）
  ↓ 召回候选集
Layer 2: 图谱关系过滤（Neo4j）
  ↓ 关系验证
Layer 3: 规则约束验证（业务规则）
  ↓ 最终结果
返回结构化数据
```

### 核心优势

- ✅ **无幻觉**：100%基于真实数据，不生成虚假信息
- ✅ **高准确性**：三层验证确保结果准确性>95%
- ✅ **安全可控**：Layer3规则验证确保业务安全
- ✅ **高性能**：总响应时间<100ms
- ✅ **可解释**：每层结果可追溯和解释

## 🏗️ 三层检索架构

### Layer 1: 向量语义检索

**技术栈**：
- 向量数据库：Qdrant
- 向量模型：GTE-Large-zh（1024维）
- 索引算法：HNSW

**功能**：
- 基于语义相似度召回候选集
- 支持中文语义理解
- 快速检索（<30ms）

**召回策略**：
- 召回数量：top_k × 2（例如需要10个结果，召回20个候选）
- 相似度阈值：>0.6
- 支持多模态查询（文本+结构化条件）

### Layer 2: 图谱关系过滤

**技术栈**：
- 图数据库：Neo4j
- 节点数量：3,656个
- 关系数量：46,882个

**功能**：
- 验证候选结果的关系正确性
- 扩展相关信息（如动作的目标肌群）
- 过滤不符合关系约束的结果

**关系验证**：
- 验证TARGETS_PRIMARY/SECONDARY关系
- 验证REQUIRES关系（器械要求）
- 验证CONTRAINDICATED_FOR关系（禁忌症）

### Layer 3: 规则约束验证

**技术栈**：
- Python业务规则引擎
- 用户档案数据
- 安全约束规则

**功能**：
- 验证用户特定约束（损伤、疾病、过敏）
- 验证业务规则（难度匹配、器械可用性）
- 排序和截断到top_k

**验证规则**：
- 禁忌症检查：排除用户禁忌动作
- 难度匹配：根据用户水平过滤
- 器械可用性：根据用户可用器械过滤
- 偏好匹配：根据用户偏好排序

## 🚀 使用方法

### 基本用法

```python
from src.framework.retrieval.true_three_layer_engine import TrueThreeLayerEngine

# 初始化引擎
engine = TrueThreeLayerEngine(
    neo4j_client=neo4j_client,
    qdrant_client=qdrant_client,
    embedding_model=embedding_model
)

# 执行三层检索
result = await engine.execute_three_layer_search(
    query_text="胸部训练动作",
    domain="fitness",
    top_k=10,
    context={
        "user_profile": user_profile,
        "equipment": ["杠铃", "哑铃"],
        "difficulty": "intermediate"
    }
)

# 获取结果
exercises = result.final_results
layer1_count = result.layer1_count  # Layer1召回数量
layer2_count = result.layer2_count  # Layer2过滤后数量
layer3_count = result.layer3_count  # Layer3最终数量
```

### 高级用法

#### 1. 自定义召回策略

```python
result = await engine.execute_three_layer_search(
    query_text="增肌训练",
    domain="fitness",
    top_k=10,
    context={
        "user_profile": user_profile,
        "recall_multiplier": 3,  # 召回3倍数量
        "similarity_threshold": 0.7  # 提高相似度阈值
    }
)
```

#### 2. 指定目标肌群

```python
result = await engine.execute_three_layer_search(
    query_text="胸部训练",
    domain="fitness",
    top_k=10,
    context={
        "user_profile": user_profile,
        "target_muscles": ["胸大肌", "前锯肌"],  # 指定目标肌群
        "primary_only": True  # 只返回主要目标肌群匹配的动作
    }
)
```

#### 3. 安全约束检查

```python
result = await engine.execute_three_layer_search(
    query_text="下肢训练",
    domain="fitness",
    top_k=10,
    context={
        "user_profile": user_profile,
        "safety_check": True,  # 启用安全检查
        "exclude_contraindications": True,  # 排除禁忌动作
        "risk_threshold": 0.7  # 风险阈值
    }
)
```

## 📊 性能优化

### 优化目标

| 层级 | 目标响应时间 | 当前状态 |
|------|-------------|---------|
| Layer1 (向量检索) | < 30ms | ✅ 已优化 |
| Layer2 (图谱查询) | < 50ms | ✅ 已优化 |
| Layer3 (规则验证) | < 20ms | ✅ 已优化 |
| **总体检索** | **< 100ms** | **✅ 已优化** |

### Layer1 优化建议

1. **合理设置召回数量**
   ```python
   # ✅ 推荐：召回2-3倍
   recall_multiplier = 2  # 需要10个，召回20个
   
   # ❌ 不推荐：召回过多
   recall_multiplier = 10  # 需要10个，召回100个（浪费）
   ```

2. **使用缓存**
   ```python
   # 启用查询缓存
   result = await engine.execute_three_layer_search(
       query_text="胸部训练",
       domain="fitness",
       top_k=10,
       context={"use_cache": True}  # 启用缓存
   )
   ```

3. **批量查询**
   ```python
   # 批量查询多个用户
   results = await engine.batch_search(
       queries=["胸部训练", "背部训练", "腿部训练"],
       domain="fitness",
       top_k=10
   )
   ```

### Layer2 优化建议

1. **使用索引字段查询**
   ```python
   # ✅ 使用索引字段
   context = {
       "muscle_name_zh": "胸大肌",  # 有索引
       "difficulty": "intermediate"  # 有索引
   }
   
   # ❌ 避免全文搜索
   context = {
       "description_contains": "胸部"  # 无索引，慢
   }
   ```

2. **限制关系深度**
   ```python
   # ✅ 限制关系深度
   context = {
       "max_relationship_depth": 2  # 最多2层关系
   }
   
   # ❌ 避免深度遍历
   context = {
       "max_relationship_depth": 5  # 太深，慢
   }
   ```

### Layer3 优化建议

1. **提前终止**
   ```python
   # 达到top_k后立即返回
   context = {
       "early_termination": True,  # 启用提前终止
       "top_k": 10
   }
   ```

2. **缓存用户档案**
   ```python
   # 缓存用户档案，避免重复查询
   context = {
       "user_profile": cached_user_profile,  # 使用缓存
       "cache_ttl": 3600  # 缓存1小时
   }
   ```

## 📝 常见问题

### Q1: 为什么Layer1召回很多，但Layer3结果很少？

**原因**：Layer2和Layer3的过滤规则过于严格。

**解决方案**：
```python
# 放宽约束
context = {
    "relax_constraints": True,
    "similarity_threshold": 0.5,  # 降低相似度阈值
    "risk_threshold": 0.8  # 提高风险阈值
}
```

### Q2: 检索速度慢怎么办？

**原因**：可能是召回数量过多或关系深度过深。

**解决方案**：
```python
# 优化参数
context = {
    "recall_multiplier": 2,  # 减少召回倍数
    "max_relationship_depth": 2,  # 限制关系深度
    "use_cache": True  # 启用缓存
}
```

### Q3: 如何确保结果的多样性？

**解决方案**：
```python
# 启用多样性优化
context = {
    "diversity_optimization": True,
    "diversity_threshold": 0.8  # 相似度>0.8的结果只保留一个
}
```
