## 1. 概述

本文档介绍DAML-RAG系统的监控和可观测性功能，提供完整的监控解决方案，包括结构化日志、文件日志系统、性能监控、流式输出监控、指标收集、告警系统和Grafana仪表板。

### 核心功能

- **结构化日志系统**：JSON格式日志、trace_id追踪、会话级别日志上下文
- **文件日志系统**：持久化日志存储、日志轮转、错误日志分离
- **性能监控器**：工作流监控、步骤级别性能记录、性能瓶颈检测
- **流式输出监控**：TTFB监控、生成速度监控、流式会话统计
- **指标收集**：延迟、吞吐量、错误率、资源使用指标
- **告警系统**：阈值配置、告警规则、告警触发和通知
- **Grafana仪表板**：实时指标可视化、历史趋势分析

## 2. 日志系统

### 2.1 文件日志系统

#### 概述

文件日志系统提供持久化的日志存储，支持日志轮转和错误日志分离，便于历史日志分析和问题排查。

**核心特性**:
- 双通道输出：控制台 + 文件
- 日志分级：所有日志（INFO+）和错误日志（ERROR+）
- 自动轮转：防止单个文件过大
- 按日期命名：便于日志管理
- UTF-8编码：支持中文日志

#### 日志文件位置

```bash
/app/logs/
├── daml-rag-YYYYMMDD.log        # 所有日志（INFO及以上）
└── daml-rag-error-YYYYMMDD.log  # 错误日志（ERROR及以上）
```

#### 日志轮转配置

- **所有日志文件**：
  - 最大大小：50MB
  - 备份数量：10个
  - 总容量：约500MB

- **错误日志文件**：
  - 最大大小：10MB
  - 备份数量：5个
  - 总容量：约50MB

#### 环境变量配置

```bash
# 启用/禁用文件日志（默认启用）
ENABLE_FILE_LOGGING=true

# 日志级别（默认WARNING）
LOG_LEVEL=INFO

# 启用请求日志（默认禁用）
ENABLE_REQUEST_LOGGING=false
```

#### 查看日志文件

```bash
# 查看所有日志文件
docker exec fitness_daml_rag ls -lh /app/logs/

# 查看今天的日志
docker exec fitness_daml_rag tail -f /app/logs/daml-rag-$(date +%Y%m%d).log

# 查看错误日志
docker exec fitness_daml_rag tail -f /app/logs/daml-rag-error-$(date +%Y%m%d).log

# 搜索特定内容
docker exec fitness_daml_rag grep "ERROR" /app/logs/daml-rag-20251223.log

# 统计日志行数
docker exec fitness_daml_rag wc -l /app/logs/daml-rag-20251223.log
```

#### 日志清理

```bash
# 删除7天前的日志
docker exec fitness_daml_rag find /app/logs/ -name "*.log*" -mtime +7 -delete

# 删除所有日志（谨慎使用）
docker exec fitness_daml_rag rm -f /app/logs/*.log*
```

### 2.2 结构化日志系统

#### 增强日志系统概述

增强日志系统（Enhanced Logging System）为流式会话提供结构化、详细的日志记录功能。它记录会话的完整生命周期，包括步骤执行、结构化数据检测、错误处理和性能指标。

**核心功能**:
- 会话级别日志上下文
- 步骤级别日志追踪
- 结构化数据检测日志
- 错误日志增强（包含完整堆栈和上下文）
- 性能指标日志（TTFB、生成速度、token数）

### 2.3 基本用法

#### 导入模块

```python

from framework.monitoring import get_logger, set_trace_id
```

#### 记录会话开始

```python

    request_id="abc123",

    domain="fitness"
)
```

```
query='帮我设计一个增肌计划', query_length=11, domain=fitness, 
timestamp=2025-12-20 10:30:00
```

性能监控器v2.0提供全面的工作流性能监控功能，包括步骤级别的性能记录、性能瓶颈检测和Prometheus指标导出。

**核心功能**:
- 工作流级别监控
- 步骤级别性能记录
- 性能瓶颈自动检测
- Prometheus指标导出
- 并发请求数监控

### 3.2 工作流监控

```python
from src.framework.monitoring.performance_monitor import get_performance_monitor

# 获取全局监控器实例
monitor = get_performance_monitor()

# 开始工作流监控
context = monitor.start_workflow(
    request_id="req-001",
    user_id="user-123"
)

# 记录步骤性能
monitor.record_step(
    context=context,
    step_number=1,
    step_name="用户档案加载",
    duration_ms=500.0,
    success=True,
    metadata={"cache_hit": True}
)

# 完成工作流监控
monitor.finish_workflow(
    context=context,
    success=True,
    total_duration_ms=2000.0
)
```


### 3.3 性能瓶颈检测

性能监控器会自动检测超过阈值（默认1000ms）的步骤：

```python

for bottleneck in bottlenecks:
    print(f"步骤{bottleneck.step_number}: {bottleneck.step_name}")
    print(f"耗时: {bottleneck.duration_ms}ms")
    print(f"阈值: {bottleneck.threshold_ms}ms")

# 使用自定义阈值
bottlenecks = monitor.get_bottlenecks(threshold_ms=500.0)

# 使用时间窗口（最近1小时）
bottlenecks = monitor.get_bottlenecks(time_window_seconds=3600)
```


## 4. 流式输出监控

### 4.1 流式输出监控概述

流式输出监控系统提供对流式会话的完整监控，包括性能指标收集、日志记录和统计数据查询。

**核心功能**:
- TTFB（首字节响应时间）监控
- 生成速度监控（tokens/s）
- 流式会话成功率统计
- 错误类型分布统计
- 实时监控数据查询

### 4.2 监控指标

#### StreamingMetrics 数据类

流式会话的完整监控指标：

```python
@dataclass
class StreamingMetrics:
    # 性能指标
    ttfb_ms: float  # Time To First Byte（首字节响应时间）
    total_duration_ms: float  # 总耗时
    tokens_generated: int  # 生成的token数
    tokens_per_second: float  # 生成速度
    
    # 质量指标
    success: bool  # 是否成功完成
    error_type: Optional[str]  # 错误类型
    retry_count: int  # 重试次数
    
    # 内容指标
    content_length: int  # 内容长度（字符数）
    structured_data_count: int  # 结构化数据数量
    
    # 用户指标
    user_id: str
    session_id: str
    request_id: str
    timestamp: float
```


#### 关键性能指标（KPI）

| 指标 | 目标值 | 说明 |
|------|--------|------|
| **TTFB** | < 2秒 | 首字节响应时间，影响用户感知速度 |
| **生成速度** | > 10 tokens/s | 流式生成速度，影响打字效果流畅度 |
| **成功率** | > 95% | 流式会话成功完成的比例 |
| **平均耗时** | < 60秒 | 完整生成一个回答的平均时间 |

## 5. 指标收集

### 5.1 指标收集概述

指标收集系统提供对系统运行状态的量化监控，支持计数器、仪表和直方图三种指标类型。


### 5.2 使用指标收集器

```python
from framework.monitoring import get_metrics_collector

# 获取指标收集器
metrics = get_metrics_collector()

# 记录计数器
metrics.get_metric("requests_total").inc(
    labels={"endpoint": "/api/chat", "method": "POST", "status": "200"}
)

# 记录直方图（延迟）
metrics.get_metric("request_duration_seconds").observe(
    0.85,
    labels={"endpoint": "/api/chat", "method": "POST"}
)

# 记录仪表（资源使用）
metrics.get_metric("cpu_usage_percent").set(75.5)
```

### 5.3 注册自定义指标

```python
from framework.monitoring import get_metrics_collector

metrics = get_metrics_collector()

# 注册计数器
counter = metrics.register_counter(
    "custom_events_total",
    "自定义事件总数",
    labels=["event_type", "status"]
)

# 注册仪表
gauge = metrics.register_gauge(
    "queue_size",
    "队列大小",
    labels=["queue_name"]
)

# 注册直方图
histogram = metrics.register_histogram(
    "processing_duration_seconds",
    "处理耗时（秒）",
    labels=["operation"],
    buckets=[0.1, 0.5, 1.0, 2.0, 5.0]
)
```

### 5.4 使用指标

```python
# 计数器
counter.inc(labels={"event_type": "user_login", "status": "success"})

# 仪表
gauge.set(42, labels={"queue_name": "tasks"})
gauge.inc(5, labels={"queue_name": "tasks"})
gauge.dec(3, labels={"queue_name": "tasks"})

# 直方图
histogram.observe(1.23, labels={"operation": "database_query"})

# 获取统计
stats = histogram.get_statistics(labels={"operation": "database_query"})
print(f"P95: {stats['p95']:.2f}s")
```

## 6. Prometheus指标

### 6.1 工作流指标

| 指标名称 | 类型 | 说明 |
|---------|------|------|
| `workflow_total_duration_seconds` | histogram | 工作流总耗时（秒） |
| `workflow_step_duration_seconds{step="..."}` | histogram | 步骤耗时（秒） |
| `workflow_success_total` | counter | 工作流成功总数 |
| `workflow_failure_total` | counter | 工作流失败总数 |
| `workflow_success_rate` | gauge | 工作流成功率 |
| `workflow_bottleneck_total` | counter | 性能瓶颈总数 |
| `workflow_concurrent_requests` | gauge | 当前并发请求数 |

### 6.2 分位数

所有histogram类型的指标都包含以下分位数：
- `quantile="0.5"`: 中位数（P50）
- `quantile="0.9"`: P90
- `quantile="0.95"`: P95
- `quantile="0.99"`: P99

### 6.3 导出指标到Prometheus

```python
from flask import Flask, Response

app = Flask(__name__)

@app.route('/metrics')
def metrics():
    """Prometheus指标端点"""
    metrics = monitor.export_metrics(format="prometheus")
    return Response(metrics, mimetype='text/plain')
```

#### 资源指标

- **Memory Usage**: 内存使用量

#### 业务指标
- **Cache Hit Rate**: 缓存命中率
- **Retrieval Duration**: 检索耗时
- **LLM Call Duration**: LLM调用耗时

## 8. 告警系统

### 8.1 配置告警规则

```python
from framework.monitoring import get_alert_system, AlertRule, AlertSeverity

alert_system = get_alert_system()

# 添加响应时间告警
alert_system.add_rule(AlertRule(
    name="high_response_time",
    description="响应时间过高",
    metric_name="request_duration_seconds",
    condition="gt",
    threshold=5.0,
    severity=AlertSeverity.WARNING,
    duration_seconds=60,  # 持续60秒才触发

    threshold=0.1,
    severity=AlertSeverity.ERROR,
    duration_seconds=60
))
```

## 9. 故障排查

### 9.1 日志问题

**问题**: 日志没有输出

**解决**:
```python
import logging
logging.basicConfig(level=logging.INFO)
```

**问题**: trace_id为None

**解决**:
```python
from framework.monitoring import set_trace_id
trace_id = set_trace_id()  # 确保调用
```

**问题**: 会话上下文不存在

**症状**:
```
⚠️ [abc123] 会话上下文不存在，无法记录步骤开始
```

**解决方案**:
```python
# 先创建会话上下文
log_context = enhanced_logger.log_session_start(...)

# 然后才能记录步骤
enhanced_logger.log_step_start(...)
```

### 9.2 指标问题

**问题**: 指标没有记录

**解决**:
```python
# 确保指标已注册
metrics = get_metrics_collector()
metric = metrics.get_metric("your_metric_name")
if metric is None:
    metric = metrics.register_counter("your_metric_name", "描述")
```

**问题**: Prometheus无法抓取指标

**解决**:
- 检查 `/api/health/metrics/prometheus` 端点是否可访问
- 检查Prometheus配置中的target地址
- 检查网络连接


### 9.3 性能监控问题

**问题**: 指标不更新

**原因**: 使用了多个监控器实例

**解决**: 始终使用 `get_performance_monitor()` 获取全局实例

**问题**: 内存占用过高

**原因**: 历史记录过多

**解决**: 调整 `max_history_size` 参数或定期重置统计

```python
# 重置统计数据
monitor.reset_statistics()
```

**问题**: 瓶颈检测不准确

**原因**: 阈值设置不合理

**解决**: 根据实际情况调整阈值

```python
# 创建监控器时设置阈值
monitor = PerformanceMonitor(bottleneck_threshold_ms=500.0)

# 或在查询时使用自定义阈值
bottlenecks = monitor.get_bottlenecks(threshold_ms=500.0)
```

### 9.4 流式监控问题

**问题**: 监控数据为空

**排查步骤**:

3. 检查监控器是否正确初始化

**问题**: TTFB为None

**排查步骤**:
1. 检查流式生成是否成功开始
2. 检查是否有chunk返回
3. 检查日志中是否有"首字节响应"记录

**问题**: 错误类型统计不准确

**排查步骤**:

2. 检查error_type是否正确设置
3. 检查日志中的错误记录

**解决**:

### 10.6 性能优化建议

#### TTFB过高（> 3秒）

**可能原因**：
- 步骤1-9执行时间过长
- 数据库查询慢
- MCP工具调用超时

**优化方案**：
- 优化数据库查询（添加索引）
- 启用用户档案缓存
- 并行执行MCP工具调用


#### 生成速度过慢（< 5 tokens/s）

**可能原因**：
- DeepSeek API响应慢
- 网络延迟高
- 服务器负载高

**优化方案**：
- 检查网络连接质量
- 增加服务器资源
- 考虑使用更快的模型

#### 成功率过低（< 95%）

**可能原因**：
- 超时设置过短
- API限流
- 错误处理不完善

**优化方案**：
- 增加超时时间（180秒 → 300秒）
- 实现重试机制
- 完善错误处理和降级策略

#### 定期检查瓶颈

```python
# 每小时检查一次性能瓶颈
bottlenecks = monitor.get_bottlenecks(time_window_seconds=3600)

if len(bottlenecks) > 10:
    logger.warning(f"发现{len(bottlenecks)}个性能瓶颈，需要优化")
    
    # 按步骤分组统计
    step_bottlenecks = defaultdict(list)
    for b in bottlenecks:
        step_bottlenecks[b.step_name].append(b.duration_ms)
    
    # 找出最慢的步骤
    for step_name, durations in step_bottlenecks.items():
        avg_duration = sum(durations) / len(durations)
        logger.warning(f"步骤 {step_name} 平均耗时: {avg_duration:.0f}ms")
```

#### 监控并发请求数

```python
# 检查当前并发请求数
concurrent = monitor.prometheus_metrics["workflow_concurrent_requests"]

if concurrent > 80:  # 接近最大并发限制100
    logger.warning(f"并发请求数过高: {concurrent}/100")
```
