---

## 📋 概述

本指南说明如何配置DAML-RAG系统的日志级别，以减少不必要的日志输出，只在错误时输出详细信息。

---

## 🔧 配置方法

### 1. 环境变量配置

在`.env`文件中添加以下配置：

```bash
# 日志级别: DEBUG, INFO, WARNING, ERROR, CRITICAL
LOG_LEVEL=WARNING

# 是否启用请求日志（true/false）
ENABLE_REQUEST_LOGGING=false
```

### 2. 日志级别说明

| 级别 | 说明 | 输出内容 |
|------|------|---------|
| DEBUG | 调试模式 | 所有日志（包括请求详情） |
| INFO | 信息模式 | 一般信息和警告/错误 |
| WARNING | 警告模式（推荐） | 只输出警告和错误 |
| ERROR | 错误模式 | 只输出错误 |
| CRITICAL | 严重错误模式 | 只输出严重错误 |

**推荐配置**：
- 开发环境：`LOG_LEVEL=INFO`
- 生产环境：`LOG_LEVEL=WARNING`
- 调试问题：`LOG_LEVEL=DEBUG` + `ENABLE_REQUEST_LOGGING=true`

## 🚀 应用配置

### 方法1：修改.env文件后重启容器

```bash
# 修改.env文件
LOG_LEVEL=WARNING
ENABLE_REQUEST_LOGGING=false

# 重启容器
docker restart fitness_daml_rag
```

### 方法2：临时设置环境变量

```bash
# Windows
docker exec -e LOG_LEVEL=DEBUG fitness_daml_rag python your_script.py

# Linux/Mac
docker exec -e LOG_LEVEL=DEBUG fitness_daml_rag python your_script.py
```

## 🔍 日志输出位置

### 1. 容器日志
```bash
# 查看实时日志
docker logs -f fitness_daml_rag

# 查看最近100行
docker logs --tail 100 fitness_daml_rag

# 只看错误
docker logs fitness_daml_rag 2>&1 | findstr "ERROR"
```

### 2. 文件日志
日志文件位置：`daml-rag-server/logs/`（如果配置了文件输出）

## ⚙️ 高级配置

### 针对特定模块设置日志级别

在代码中：

```python
import logging

# 设置特定模块的日志级别
logging.getLogger('uvicorn.access').setLevel(logging.WARNING)
logging.getLogger('httpx').setLevel(logging.WARNING)
```

### 自定义日志格式

修改`src/api/config/logging_config.py`：

```python
logging.basicConfig(
    level=ACTUAL_LOG_LEVEL,
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',
    datefmt='%Y-%m-%d %H:%M:%S'
)
```

## 📝 最佳实践

1. **生产环境使用WARNING级别**
   - 减少日志量
   - 只关注问题
   - 提高性能

2. **调试时临时开启DEBUG**
   - 不要永久设置为DEBUG
   - 调试完成后恢复WARNING

3. **关闭请求日志**
   - 除非需要审计
   - 减少日志噪音
   - 提高性能

4. **定期清理日志**
   - 避免磁盘占满
   - 使用日志轮转
