## 概述

本文档详细说明DAML-RAG服务的流式输出（SSE - Server-Sent Events）实现，包括SSE事件生成器、流式监控集成、降级策略和错误处理机制。

### 核心特性

1. **真实流式输出** - 步骤10使用真实的LLM流式调用，实时yield SSE事件
2. **降级机制** - 流式失败时自动降级到非流式模式
3. **并发限制** - 集成并发限流器，防止服务过载
4. **性能监控** - 完整的流式会话指标记录（TTFB、吞吐量、成功率）
5. **错误处理** - 多层错误处理和重试机制

### 技术架构

```
前端请求 → FastAPI路由 → 并发限制检查 → SSE事件生成器
                                              ↓
                                    流式工作流执行器
                                    （步骤1-9同步）
                                              ↓
                                    步骤10：LLM流式调用
                                              ↓
                                    实时yield SSE事件
                                              ↓
                                    流式失败？→ 降级到非流式
                                              ↓
                                    释放并发许可
```

## 核心组件

### 1. SSE路由端点

**文件路径**: `src/api/routes/chat.py`

**函数签名**:
```python
@router.post("/v1/chat/stream")
async def chat_stream(request: Dict[str, Any]):
    """
    流式聊天接口（SSE - Server-Sent Events）
    
    使用场景：
    - 前端需要实时显示AI打字效果
    - 长文本响应的渐进式呈现（突破4096 token限制）
    - 提升用户体验
    
    技术实现：
    1. 检查并发限制
    2. 执行步骤1-9（同步）
    3. 步骤10使用真实的LLM流式调用
    4. 实时yield SSE事件给前端
    5. 流式失败时自动降级到非流式模式
    6. 释放并发许可
```

**核心代码**:

### 2. 并发限制检查

**目的**: 防止服务过载，限制同时处理的流式请求数量

**代码实现**:
```python
# 2. 并发限制检查
from ...framework.monitoring.concurrency_limiter import concurrency_limiter

# 尝试获取连接许可（等待最多5秒）
acquired = await concurrency_limiter.acquire(
    user_id=user_id,
    session_id=session_id,
    timeout=5.0
)

if not acquired:
    # 并发限制：返回503错误
    logger.warning(
        f"⚠️ 并发限制：拒绝连接 user={user_id}, session={session_id[:8]}..."
    )
    
    # 返回SSE格式的错误响应
    async def rate_limit_generator():
        yield {
            "event": "rate_limit",
            "data": json.dumps({
                "type": "rate_limit",
                "message": "服务繁忙，请稍后重试",
                "retry_after": 10
            }, ensure_ascii=False)
        }
    
    from sse_starlette.sse import EventSourceResponse
    return EventSourceResponse(
        rate_limit_generator(),
        status_code=503,
        headers={
            "Retry-After": "10",
            "Cache-Control": "no-cache"
        }
    )
```

**关键点**:
- 使用`concurrency_limiter.acquire()`获取许可
- 超时时间设置为5秒
- 拒绝时返回503状态码和`rate_limit`事件
- 提供`Retry-After`头部，建议客户端10秒后重试

## SSE事件生成器

### 3. 事件生成器核心逻辑

**函数签名**:
```python
async def event_generator():
    """SSE事件生成器 - 使用真实的流式工作流，失败时降级"""
```

**核心流程**:

#### 3.1 初始化流式会话指标

```python
from ...framework.monitoring.streaming_metrics import (
    StreamingSessionMetrics,
    record_streaming_metrics
)

metrics = StreamingSessionMetrics(
    session_id=session_id,
    user_id=user_id,
    start_time=time.time()
)

first_byte_sent = False
total_tokens = 0
```

**指标说明**:
- `session_id`: 会话唯一标识
- `user_id`: 用户ID
- `start_time`: 会话开始时间
- `first_byte_sent`: 是否已发送首字节（用于计算TTFB）
- `total_tokens`: 累计生成的令牌数

#### 3.2 执行流式工作流

```python
try:
    # 导入流式工作流执行器
    from ...applications.fitness.workflow_executor import execute_eleven_step_workflow_stream
    
    # 执行流式工作流，逐个yield事件
    async for event in execute_eleven_step_workflow_stream(
        query_text=query_text,
        user_id=user_id,
        domain=domain,
        user_profile=None,
        session_id=session_id
    ):
        # 记录首字节时间（TTFB）
        if not first_byte_sent:
            metrics.first_byte_time = time.time()
            first_byte_sent = True
            logger.debug(f"📊 首字节发送: TTFB={metrics.ttfb:.2f}s, session={session_id[:8]}...")
        
        # 统计令牌数（如果事件包含content）
        if event.get("type") == "chunk" and "content" in event:
            content = event["content"]
            total_tokens += len(content)
        
        # 发送SSE事件
        yield {
            "event": event["type"],
            "data": json.dumps(event, ensure_ascii=False)
        }
```

**关键点**:
- 使用`async for`循环逐个yield事件
- 首次发送时记录TTFB（Time To First Byte）
- 统计生成的令牌数（简单估算：中文按字符数）
- 每个事件包含`event`类型和`data`数据


#### 3.3 流式成功完成

```python
# 流式成功完成
metrics.end_time = time.time()
metrics.total_tokens = total_tokens
metrics.success = True

# 记录指标到Prometheus
try:
    record_streaming_metrics(metrics)
    logger.info(
        f"✅ 流式会话完成: session={session_id[:8]}..., "
        f"TTFB={metrics.ttfb:.2f}s, duration={metrics.duration:.2f}s, "
        f"tokens={total_tokens}, rate={metrics.tokens_per_second:.1f} tokens/s"
    )
except Exception as metric_error:
    logger.warning(f"⚠️ 指标记录失败（不影响主业务）: {metric_error}")
```

**指标记录**:
- `TTFB`: 首字节响应时间（Time To First Byte）
- `duration`: 总持续时间
- `tokens`: 生成的令牌总数
- `tokens_per_second`: 吞吐量（令牌/秒）

## 降级策略

### 4. 流式失败降级机制

**触发条件**: 流式工作流执行过程中抛出异常

**降级流程**:

#### 4.1 捕获流式错误

```python
except Exception as stream_error:
    logger.error(f"⚠️ 流式生成失败，尝试降级到非流式模式: {stream_error}", exc_info=True)
    stream_failed = True
    
    # 记录失败指标
    metrics.end_time = time.time()
    metrics.total_tokens = total_tokens
    metrics.success = False
    metrics.error_message = str(stream_error)
    
    try:
        record_streaming_metrics(metrics)
        logger.info(
            f"❌ 流式会话失败: session={session_id[:8]}..., "
            f"error={stream_error}, duration={metrics.duration:.2f}s"
        )
    except Exception as metric_error:
        logger.warning(f"⚠️ 失败指标记录失败: {metric_error}")
```

#### 4.2 发送降级通知

```python
# 发送降级通知事件
yield {
    "event": "fallback",
    "data": json.dumps({
        "type": "fallback",
        "message": "流式输出暂时不可用，切换到标准模式",
        "reason": "stream_error"
    }, ensure_ascii=False)
}
```

**前端处理**:
- 前端收到`fallback`事件后，应显示提示信息
- 继续接收后续的`chunk`事件（降级模式）

#### 4.3 执行非流式工作流

```python
try:
    logger.info(f"🔄 降级：使用非流式工作流")
    
    # 调用非流式工作流
    workflow_result = await execute_eleven_step_workflow(
        query_text=query_text,
        user_id=user_id,
        domain=domain,
        user_profile=None,
        session_id=session_id
    )
    
    # 提取响应
    eleven_step_data = workflow_result.get("eleven_step_workflow", {})
    fallback_response = eleven_step_data.get("final_response", "抱歉，暂时无法生成回答，请稍后重试。")
```

#### 4.4 模拟流式发送

```python
# 模拟流式发送（分块发送非流式响应）
chunk_size = 50
for i in range(0, len(fallback_response), chunk_size):
    chunk = fallback_response[i:i+chunk_size]
    yield {
        "event": "chunk",
        "data": json.dumps({
            "type": "chunk",
            "content": chunk,
            "fallback": True
        }, ensure_ascii=False)
    }
    await asyncio.sleep(0.05)  # 模拟延迟

# 发送完成事件
yield {
    "event": "done",
    "data": json.dumps({
        "type": "done",
        "data": {
            "request_id": session_id,
            "total_length": len(fallback_response),
            "fallback": True,
            "success": True
        }
    }, ensure_ascii=False)
}
```

**关键点**:
- 将完整响应分成50字符的块
- 每块之间延迟50ms，模拟打字效果
- 在事件中标记`fallback: True`，告知前端这是降级模式

#### 4.5 记录降级成功指标

```python
# 记录降级成功的指标（作为成功会话）
metrics.end_time = time.time()
metrics.total_tokens = len(fallback_response)
metrics.success = True

try:
    record_streaming_metrics(metrics)
    logger.info(
        f"✅ 降级成功：非流式模式返回响应（长度: {len(fallback_response)}字）, "
        f"duration={metrics.duration:.2f}s"
    )
except Exception as metric_error:
    logger.warning(f"⚠️ 降级成功指标记录失败: {metric_error}")
```


#### 4.6 降级失败处理

```python
except Exception as fallback_error:
    logger.error(f"❌ 降级失败：非流式模式也失败: {fallback_error}", exc_info=True)
    
    # 记录降级失败的指标
    metrics.end_time = time.time()
    metrics.success = False
    metrics.error_message = f"Stream failed, fallback also failed: {str(fallback_error)}"
    
    try:
        record_streaming_metrics(metrics)
    except Exception as metric_error:
        logger.warning(f"⚠️ 降级失败指标记录失败: {metric_error}")
    
    # 发送最终错误事件
    yield {
        "event": "error",
        "data": json.dumps({
            "type": "error",
            "error": f"服务暂时不可用: {str(fallback_error)}",
            "fallback_failed": True
        }, ensure_ascii=False)
    }
```

**错误处理层次**:
1. **流式失败** → 尝试降级到非流式
2. **降级失败** → 返回错误事件
3. **指标记录失败** → 仅记录警告，不影响主流程

## 流式工作流执行器

### 5. 流式工作流核心实现

**文件路径**: `src/applications/fitness/workflow_executor.py`

**函数签名**:

```python
async def execute_eleven_step_workflow_stream(
    query_text: str,
    user_id: str,
    domain: str = "fitness",
```

```python
# ===== 步骤1-2：并行执行（优化TTFB） =====
yield {
    "type": "step",
    "step": 1,
    "message": "正在加载用户档案和初始化会话..."
}

# 创建步骤性能记录
step1_perf = perf_monitor.create_step(1, "预加载用户档案")
step2_perf = perf_monitor.create_step(2, "会话记录存储")

# 定义步骤1：预加载用户档案
async def load_user_profile():
    step1_perf.start()
    nonlocal user_profile
    
    if not user_profile and user_id:
        try:
            # ... 加载用户档案逻辑 ...
            step1_perf.finish(success=True, profile_loaded=bool(user_profile))
        except Exception as e:
            step1_perf.finish(success=False, error=str(e))
    
    return user_profile

# 定义步骤2：会话记录存储
async def create_session():
    step2_perf.start()
    nonlocal session_id
    
    if not session_id:
        session_id = f"session_{user_id or 'anonymous'}_{int(time.time())}"
    
    step2_perf.finish(success=True, session_id=session_id[:16])
    return session_id

# 并行执行步骤1和步骤2
parallel_start = time.time()
user_profile, session_id = await asyncio.gather(
    load_user_profile(),

parallel_duration = (time.time() - parallel_start) * 1000
logger.info(f"✅ [{request_id}] 步骤1-2并行完成，总耗时: {parallel_duration:.2f}ms")
```

**并行执行优势**:
- 减少总执行时间
- 优化TTFB（Time To First Byte）

#### 5.3 步骤10：LLM流式生成

**关键代码**:
```python
# ===== 步骤10：LLM流式生成最终回答 =====
yield {
    "type": "step",
    "step": 10,
    "message": "AI正在生成回答..."
}

step10_perf = perf_monitor.create_step(10, "LLM流式生成")
step10_perf.start()

try:
    from ...framework.clients.llm_client import LLMClient
    
    llm_client = LLMClient()
    
    # 构建LLM提示词
    prompt = build_llm_prompt(
        query=query_text,
        user_profile=user_profile,
        few_shot_examples=few_shot_examples,
        dag_results=dag_results
    )
    
    # 流式调用LLM
    full_response = ""
    async for chunk in llm_client.generate_stream(
        prompt=prompt,
        model=model_choice,
        temperature=0.7,
        max_tokens=4096
    ):
        # 提取文本内容
        content = chunk.get("content", "")
        if content:
            full_response += content
            
            # 实时yield chunk事件
            yield {
                "type": "chunk",
                "content": content,
                "done": False
            }
    
    step10_perf.finish(success=True, response_length=len(full_response))
    logger.info(f"✅ [{request_id}] 步骤10完成: 生成{len(full_response)}字")
    
except Exception as e:
    step10_perf.finish(success=False, error=str(e))
    logger.error(f"❌ [{request_id}] 步骤10失败: {e}")
    raise  # 抛出异常，触发降级机制
```

**流式生成流程**:
1. 构建LLM提示词（包含用户档案、Few-Shot示例、DAG结果）
2. 调用`llm_client.generate_stream()`进行流式生成
3. 使用`async for`循环逐个接收chunk
4. 每个chunk立即yield给前端
5. 累积完整响应用于后续处理

## SSE事件类型

### 6. 事件类型定义

#### 6.1 step事件

**用途**: 通知前端当前执行的步骤

**格式**:
```json
{
  "type": "step",
  "step": 1,
  "message": "正在加载用户档案和初始化会话..."
}
```

**字段说明**:
- `type`: 固定为`"step"`
- `step`: 步骤编号（1-11）
- `message`: 步骤描述

#### 6.2 chunk事件

**用途**: 实时发送LLM生成的文本片段

**格式**:
```json
{
  "type": "chunk",
  "content": "根据您的健身目标...",
  "done": false,
  "fallback": false
}
```

**字段说明**:
- `type`: 固定为`"chunk"`
- `content`: 文本片段
- `done`: 是否完成（最后一个chunk为true）
- `fallback`: 是否为降级模式（可选）

#### 6.3 structured_data事件

**用途**: 发送结构化数据（如训练计划、动作列表）

**格式**:
```json
{
  "type": "structured_data",
  "data_type": "training_plan",
  "data": {
    "plan_id": "plan_123",
    "exercises": [...]
  }
}
```

**字段说明**:
- `type`: 固定为`"structured_data"`
- `data_type`: 数据类型（`training_plan`、`exercise_list`等）
- `data`: 结构化数据对象

#### 6.4 done事件

**用途**: 通知前端流式输出完成

**格式**:
```json
{
  "type": "done",
  "data": {
    "request_id": "abc123",
    "session_id": "session_456",
    "total_length": 8500,
    "total_duration_ms": 3200,
    "model_used": "teacher",
    "template_id": "comprehensive_fitness_coach",
    "success": true,
    "fallback": false
  }
}
```

**字段说明**:
- `type`: 固定为`"done"`
- `data.request_id`: 请求ID
- `data.session_id`: 会话ID
- `data.total_length`: 响应总长度（字符数）
- `data.total_duration_ms`: 总耗时（毫秒）
- `data.model_used`: 使用的模型
- `data.template_id`: 使用的DAG模板ID
- `data.success`: 是否成功
- `data.fallback`: 是否为降级模式


#### 6.5 error事件

**用途**: 通知前端发生错误

**格式**:
```json
{
  "type": "error",
  "error": "服务暂时不可用: Connection timeout",
  "fallback_failed": true
}
```

**字段说明**:
- `type`: 固定为`"error"`
- `error`: 错误信息

```python
@dataclass
class StreamingSessionMetrics:
    """流式会话指标"""
    session_id: str
    user_id: str
    start_time: float
    first_byte_time: Optional[float] = None
    end_time: Optional[float] = None
    total_tokens: int = 0
    success: bool = False
    error_message: Optional[str] = None
    
    @property
    def ttfb(self) -> float:
        """首字节响应时间（Time To First Byte）"""
        if self.first_byte_time:
            return self.first_byte_time - self.start_time
        return 0.0
    
    @property
    def duration(self) -> float:
        """总持续时间"""
        if self.end_time:
            return self.end_time - self.start_time
        return 0.0
    
    @property
    def tokens_per_second(self) -> float:
        """吞吐量（令牌/秒）"""
        if self.duration > 0:
            return self.total_tokens / self.duration
        return 0.0
```

```python
    """
    记录流式会话指标到Prometheus
```

```typescript
/**
 * 流式聊天请求
 * @param userId 用户ID
 * @param query 查询文本
 * @param onChunk 接收文本片段的回调
 * @param onStep 接收步骤更新的回调
 * @param onDone 完成时的回调
 * @param onError 错误时的回调
 */
async function streamChat(
  userId: string,
  query: string,
  onChunk: (content: string) => void,
  onStep: (step: number, message: string) => void,
  onDone: (data: any) => void,
  onError: (error: string) => void
) {
  const response = await fetch('http://localhost:8001/v1/chat/stream', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      user_id: userId,
      query: query,
      domain: 'fitness'
    })
  });

  if (!response.ok) {
    if (response.status === 503) {
      onError('服务繁忙，请稍后重试');
    } else {
      onError(`请求失败: ${response.statusText}`);
    }
    return;
  }

  const reader = response.body?.getReader();
  const decoder = new TextDecoder();

  if (!reader) {
    onError('无法读取响应流');
    return;
  }

  try {
    while (true) {
      const { done, value } = await reader.read();
      
      if (done) {
        break;
      }

      // 解码数据
      const chunk = decoder.decode(value, { stream: true });
      
      // 按行分割（SSE格式）
      const lines = chunk.split('\n');
      
      for (const line of lines) {
        if (line.startsWith('data: ')) {
          const data = line.substring(6);
          
          try {
            const event = JSON.parse(data);
            
            // 处理不同类型的事件
            switch (event.type) {
              case 'step':
                onStep(event.step, event.message);
                break;
              
              case 'chunk':
                onChunk(event.content);
                break;
              
              case 'done':
                onDone(event.data);
                break;
              
              case 'error':
                onError(event.error);
                break;
              
              case 'fallback':
                console.warn('流式输出降级:', event.message);
                break;
              
              case 'rate_limit':
                onError(event.message);
                break;
            }
          } catch (e) {
            console.error('解析SSE事件失败:', e);
          }
        }
      }
    }
  } catch (error) {
    onError(`连接错误: ${error}`);
  } finally {
    reader.releaseLock();
  }
}
```

```python
def stream_chat(user_id: str, query: str):

    流式聊天客户端

        user_id: 用户ID

    # 逐行读取SSE事件

        if line:

            # 解析SSE格式
            if line_str.startswith('data: '):
                data_str = line_str[6:]  # 去掉 "data: " 前缀

                    event_type = event.get('type')
                    
                    if event_type == 'step':
                        print(f"📍 步骤 {event['step']}: {event['message']}")
                    
                    elif event_type == 'chunk':
                        # 实时打印文本片段（不换行）
                        print(event['content'], end='', flush=True)
                    
                    elif event_type == 'done':
                        print("\n\n✅ 流式输出完成")
                        data = event.get('data', {})
                        print(f"   - 请求ID: {data.get('request_id')}")
                        print(f"   - 总长度: {data.get('total_length')} 字")
                        print(f"   - 总耗时: {data.get('total_duration_ms'):.0f} ms")
                        print(f"   - 使用模型: {data.get('model_used')}")
                    
                    elif event_type == 'error':
                        print(f"\n\n❌ 错误: {event.get('error')}")
                    
                    elif event_type == 'fallback':
                        print(f"\n⚠️ 降级: {event.get('message')}")
                    
                    elif event_type == 'rate_limit':
                        print(f"\n⚠️ 限流: {event.get('message')}")
                
                except json.JSONDecodeError as e:
                    print(f"\n⚠️ 解析事件失败: {e}")
```

### 15. 并发控制

**目的**: 防止服务过载，保证服务质量

**实现**:

```python
class ConcurrencyLimiter:
    """并发限流器"""
    
    def __init__(self, max_concurrent: int = 50):
        self.max_concurrent = max_concurrent
        self.semaphore = asyncio.Semaphore(max_concurrent)
        self.active_sessions = {}
    
    async def acquire(self, user_id: str, session_id: str, timeout: float = 5.0) -> bool:
        """
        获取并发许可
        
        Args:
            user_id: 用户ID
            session_id: 会话ID
            timeout: 超时时间（秒）
        
        Returns:
            bool: 是否成功获取许可
        """
        try:
            # 尝试在超时时间内获取许可
            acquired = await asyncio.wait_for(
                self.semaphore.acquire(),
                timeout=timeout
            )
            
            if acquired:
                self.active_sessions[session_id] = {
                    "user_id": user_id,
                    "start_time": time.time()
                }
                return True
            
            return False
        
        except asyncio.TimeoutError:
            logger.warning(f"并发限制：获取许可超时 user={user_id}")
            return False
    
    async def release(self, session_id: str):
        """释放并发许可"""
        if session_id in self.active_sessions:
            del self.active_sessions[session_id]
            self.semaphore.release()
```

**配置建议**:
- 开发环境: `max_concurrent=10`
- 生产环境: `max_concurrent=50`
- 高负载环境: `max_concurrent=100`

## 故障排查

### 19. 常见问题

#### 19.1 TTFB过高（>2秒）

**可能原因**:
- 用户档案加载慢
- BGE复杂度分类慢
- 数据库连接慢

**解决方案**:
1. 检查缓存命中率
2. 优化数据库查询
3. 增加连接池大小
4. 启用步骤并行执行

#### 19.2 流式输出中断

**可能原因**:
- LLM服务不可用
- 网络连接中断
- 超时

**解决方案**:
1. 检查LLM服务状态
2. 增加超时时间
3. 启用降级机制
4. 检查网络配置

#### 19.3 并发限制频繁触发

**可能原因**:
- 并发数设置过低
- 请求处理时间过长
- 未正确释放许可

**解决方案**:
1. 增加`max_concurrent`配置
2. 优化请求处理速度
3. 检查`finally`块是否正确释放许可
4. 监控活跃连接数

#### 19.4 降级频繁发生

**可能原因**:
- LLM服务不稳定
- 网络不稳定
- 超时配置过短

**解决方案**:
1. 检查LLM服务健康状态
2. 增加重试次数
3. 调整超时配置
4. 使用LLMFallbackManager
