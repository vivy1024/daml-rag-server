# 步骤7 - DAG编排执行

**版本**: v1.1.0
**创建日期**: 2026-02-21
**状态**: 持续更新

---

## 概述

步骤7根据步骤6.5选择的 DAG 模板ID，执行对应的 DAG 工作流。DAG 中的每个任务可能调用 MCP 工具（如用户档案查询、食物营养查询、训练计划生成等），最终返回结构化的执行结果。

### 在工作流中的位置

```
步骤6.5: LLM选择DAG方案
  ↓  dag_template_id
步骤7: DAG编排执行 ⭐ ← 当前
  ↓  输出 dag_results → 写入 WorkflowState
步骤8: 三层检索（如果DAG已有结果则跳过）
```

## 函数签名

```python
async def node_execute_dag(
    state: WorkflowState,
    dag_orchestrator=None,
    mcp_tool_manager=None,
    template_manager=None
) -> StateUpdate:
```

### 参数说明

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `state` | `WorkflowState` | ✅ | 当前工作流状态，包含 `request_id`、`dag_template_id`、`user_profile`、`session_id`、`query_text`、`user_id` |
| `dag_orchestrator` | `EnhancedDAGOrchestrator \| None` | ❌ | DAG编排器，未传入时自动创建 |
| `mcp_tool_manager` | `MCPToolManager \| None` | ❌ | MCP工具管理器，传递给编排器 |
| `template_manager` | `DAGTemplateManager \| None` | ❌ | DAG模板管理器，未传入时自动创建 |

### 返回值

```python
StateUpdate(updates={
    "dag_results": Dict[str, Any] | None,  # DAG执行结果（任务名 → 结果）
    "_dag_tasks_completed": int,           # 成功任务数
    "_dag_tasks_failed": int,              # 失败任务数
})
```

---

## 执行逻辑

### 1. 检查模板ID

```python
selected_template_id = state.get("dag_template_id")

if not selected_template_id:
    return StateUpdate(updates={"dag_results": None}, warning="无DAG模板ID")
```

### 2. 初始化编排器

```python
from ..enhanced_dag_orchestrator import EnhancedDAGOrchestrator
from ..dag_template_system import DAGTemplateManager

if template_manager is None:
    template_manager = DAGTemplateManager()

if dag_orchestrator is None:
    dag_orchestrator = EnhancedDAGOrchestrator(
        template_manager=template_manager,
        mcp_orchestrator=mcp_tool_manager
    )
```

### 3. 执行DAG模板

```python
dag_execution_result = await dag_orchestrator.execute_template(
    template_id=selected_template_id,
    user_profile=user_profile or {},
    session_context={
        "session_id": session_id,
        "query": query_text,
        "_context": {
            "user_id": user_id,
            "query": query_text,
            "session_id": session_id,
            "user_profile": user_profile
        }
    },
    cached_results=None
)
```

**关键点**：`_context` 字段包含完整的工作流状态，供 `ParameterExtractor` 在 MCP 工具参数提取时回退使用。

### 4. 提取结果

```python
dag_results = dag_execution_result.results

if dag_results:
    return StateUpdate(updates={
        "dag_results": dag_results,
        "_dag_tasks_completed": dag_execution_result.tasks_completed,
        "_dag_tasks_failed": dag_execution_result.tasks_failed
    })
```

---

## DAG执行结果结构

`dag_results` 是一个字典，键为任务名，值为任务执行结果：

```python
{
    "user_profile_query": {
        "success": True,
        "data": {...},
        "error": None
    },
    "food_nutrition_query": {
        "success": True,
        "data": {...},
        "error": None
    },
    "training_plan_generation": {
        "success": False,
        "data": None,
        "error": "权限不足",
        "fallback_used": True
    }
}
```

---

## 错误处理

| 场景 | 处理方式 | 返回值 |
|------|---------|--------|
| 无 `dag_template_id` | 跳过执行 | `dag_results=None` + `warning` |
| DAG执行返回空结果 | 记录 warning | `dag_results=None` + `warning` |
| DAG执行异常 | `except Exception` 捕获 | `dag_results=None` + `error` |

---

## 与后续步骤的数据流

### 输出到步骤8（三层检索）

如果 `dag_results` 非空，步骤8会跳过检索，直接使用 DAG 结果。

### 输出到步骤9（工具结果汇总）

`state["dag_results"]` 中的 MCP 工具调用结果会被提取和汇总。

### 输出到步骤10（LLM深度分析）

`state["dag_results"]` 作为 LLM 提示词的一部分，提供结构化数据支持。
