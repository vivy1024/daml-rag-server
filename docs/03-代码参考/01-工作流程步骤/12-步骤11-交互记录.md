```
步骤10: LLM深度分析
  ↓  final_response
步骤11: 交互记录 ⭐ ← 当前（工作流结束）
  ↓  输出 interaction_logged, _interaction_db_id
```

## 函数签名

```python
async def node_log_interaction(
    state: WorkflowState,
    backend_client=None
) -> StateUpdate:
```

### 参数说明

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `state` | `WorkflowState` | ✅ | 当前工作流状态，包含所有步骤的输出 |
| `backend_client` | `BackendClient \| None` | ❌ | 后端客户端，用于保存会话记录 |

### 返回值

```python
StateUpdate(updates={
    "interaction_logged": bool,         # 是否成功记录
    "_interaction_db_id": int | None,   # 数据库记录ID
})
```

---

## 执行逻辑

### 1. 检查后端客户端

```python
if not backend_client:
    return StateUpdate(updates={"interaction_logged": False})
```

### 2. 转换 user_id

```python
user_id_int = None
if isinstance(user_id, int):
    user_id_int = user_id
elif isinstance(user_id, str) and user_id.isdigit():
    user_id_int = int(user_id)

if not user_id_int:
    # 匿名用户，跳过记录
    return StateUpdate(updates={"interaction_logged": False})
```

### 3. 计算检索层数

```python
retrieval_layers_count = 0
if retrieval_results:
    layer_results = retrieval_results.get("layer_results", {})
    if layer_results:
        retrieval_layers_count = len(layer_results)
    elif retrieval_results.get("results"):
        retrieval_layers_count = 1
```

### 4. 保存会话记录

```python
result_data = await backend_client.save_chat_session(
    session_id=session_id,
    user_id=user_id_int,
    user_query=query_text,
    llm_response=final_response,
    model_used=selected_model,
    tools_used=mcp_tools_called,
    metadata={
        "graphrag_service": True,
        "quality_score": None,
        "retrieval_layers": retrieval_layers_count,
        "workflow_steps": 11,
        "is_complex": complexity_level == "complex",
        "few_shot_count": len(few_shot_examples),
        "dag_template_id": dag_template_id,
        "mcp_tools_count": len(mcp_tools_called),
        "request_id": request_id,
        "awaiting_user_feedback": True
    },
    qdrant_point_id=None
)
```

---

## 保存的元数据

| 字段 | 类型 | 说明 |
|------|------|------|
| `graphrag_service` | bool | 标识为 DAML-RAG 服务 |
| `quality_score` | float \| None | 质量评分（初始为 None，等待评分） |
| `retrieval_layers` | int | 检索层数（0-3） |
| `workflow_steps` | int | 工作流步骤数（固定为 11） |
| `is_complex` | bool | 是否复杂查询 |
| `few_shot_count` | int | Few-Shot 示例数量 |
| `dag_template_id` | str | 使用的 DAG 模板ID |
| `mcp_tools_count` | int | MCP 工具调用数量 |
| `request_id` | str | 请求ID（用于日志追踪） |
| `awaiting_user_feedback` | bool | 等待用户反馈（固定为 True） |

---

## 错误处理

| 场景 | 处理方式 | 返回值 |
|------|---------|--------|
| 无后端客户端 | 跳过记录 | `interaction_logged=False` + `warning` |
| 匿名用户 | 跳过记录 | `interaction_logged=False` |
| 保存失败 | `except Exception` 捕获 | `interaction_logged=False` + `warning` |

所有失败场景下工作流正常结束，不影响用户体验。

---

## 数据用途

### 1. Few-Shot 示例库

高质量的交互记录（`quality_score >= 4.0`）会被加入 Few-Shot 示例库，用于步骤6的检索。

### 2. 质量评分

用户反馈（点赞/点踩）会更新 `quality_score`，用于：
- Few-Shot 示例筛选
- 模型性能监控
- A/B 测试评估

### 3. 用户行为分析

- `mcp_tools_count`：工具使用频率
- `dag_template_id`：模板使用分布
- `is_complex`：查询复杂度分布
