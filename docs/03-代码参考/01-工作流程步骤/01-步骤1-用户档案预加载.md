# 步骤1 - 预加载用户档案

**版本**: v1.1.0
**创建日期**: 2026-02-21
**状态**: 持续更新

---

## 概述

步骤1是 DAML-RAG 工作流的入口节点，负责从缓存或后端 API 加载用户档案到 `WorkflowState`。采用**缓存优先 + 三级降级**策略，确保在任何基础设施状态下都能完成加载。加载完成后异步触发步骤3（会员权限检查）的数据预热，不阻塞主工作流。

### 在工作流中的位置

```
步骤1: 预加载用户档案 ⭐ ← 当前
  ↓  输出 user_profile → 写入 WorkflowState
  ↓  异步触发 _trigger_step3_preload（预热会员数据）
步骤2: 会话记录存储
  ↓
步骤3: 会员权限检查（使用步骤1预热的数据）
```

## 函数签名

```python
async def node_preload_user_profile(
    state: WorkflowState,
    backend_client=None,
    cache_manager=None,
    user_cache=None,
    performance_monitor=None,
    perf_context=None,
    smart_preloader=None
) -> StateUpdate:
```

### 参数说明

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `state` | `WorkflowState` | ✅ | 当前工作流状态，包含 `request_id`、`user_id`、可能已有的 `user_profile` |
| `backend_client` | `BackendClient \| None` | ❌ | 后端 API 客户端，最后降级路径 |
| `cache_manager` | `CacheManager \| None` | ❌ | 缓存管理器，主路径（缓存优先 + 自动回源） |
| `user_cache` | `UserCache \| None` | ❌ | 用户缓存层，中间降级路径 |
| `performance_monitor` | `PerformanceMonitor \| None` | ❌ | 性能监控器（预留） |
| `perf_context` | `Any \| None` | ❌ | 性能上下文（预留） |
| `smart_preloader` | `SmartPreloader \| None` | ❌ | 智能预热器，步骤3数据预热 |

### 返回值

```python
@dataclass
class StateUpdate:
    updates: Dict[str, Any]    # {"user_profile": <dict|None>}
    next_step: Optional[str]   # 本节点不设置，使用默认路由
    error: Optional[str]       # 错误信息（本节点不使用，降级为 warning）
    warning: Optional[str]     # 警告信息（无效ID / 加载失败时设置）
```

`StateUpdate.merge_into(state)` 将 `updates` 合并到 `WorkflowState`，`warning` 追加到 `state["warnings"]` 列表。

## 执行逻辑

### 快速返回路径

```python
# 1. state 中已有 user_profile → 直接返回，触发步骤3预热
if user_profile:
    await _trigger_step3_preload(user_id, smart_preloader, request_id)
    return StateUpdate(updates={"user_profile": user_profile})

# 2. 无 user_id → 返回 None，匿名模式
if not user_id:
    return StateUpdate(updates={"user_profile": None})

# 3. user_id 格式无效（非数字） → 返回 None + warning
```

### 三级降级策略

当 `user_id` 有效时，按优先级依次尝试：

```
Level 1: cache_manager（缓存优先 + 自动回源）
    ├── 缓存命中 → 直接返回（~1ms）
    └── 缓存未命中 → 调用 fetch_func 回源
         ├── user_cache.get_user_profile()
         └── backend_client.get_user_profile()
         └── 写入缓存（TTL=300s）
    ↓ cache_manager 不可用
Level 2: user_cache（直接查询用户缓存）
    ↓ user_cache 不可用
Level 3: backend_client（直接调用后端 API）
    ↓ 全部不可用或返回 None
匿名模式: user_profile = None，工作流继续执行
```

核心代码（`nodes.py` L100-134）：

```python
# Level 1: 缓存管理器
if cache_manager:
    cache_key = f"user_profile:{user_id_int}"

    async def fetch_user_profile():
        if user_cache:
            return await user_cache.get_user_profile(str(user_id_int))
        elif backend_client:
            return await backend_client.get_user_profile(user_id_int)
        return None

    user_profile = await cache_manager.get(
        key=cache_key, fetch_func=fetch_user_profile, ttl=300
    )

# Level 2: 用户缓存
elif user_cache:
    user_profile = await user_cache.get_user_profile(str(user_id_int))

# Level 3: 后端 API
elif backend_client:
    user_profile = await backend_client.get_user_profile(user_id_int)
```

## 智能预热器（步骤3数据预热）

步骤1完成后调用 `_trigger_step3_preload()`，异步预热步骤3需要的会员数据。

### 预热触发条件

- 步骤1成功加载档案 → 触发预热
- 步骤1使用已提供的档案 → 也触发预热
- `user_id` 为空 → 不触发

### 预热器选择逻辑

```python
# 1. 优先使用传入的 smart_preloader 参数
# 2. 未传入时，从 framework.storage.warmup 获取 WarmupManager
from ....framework.storage.warmup import get_warmup_manager
warmup_manager = get_warmup_manager()
await warmup_manager.preload_memberships([user_id_str])
```

### 关键特性

- **非阻塞**：预热失败不影响主工作流（`except Exception` 捕获后仅记录 warning）
- **Feature Flag**：`USE_NEW_CACHE` 环境变量控制新旧预加载器切换
- **容错**：`ImportError`（模块不存在）和运行时异常均被静默处理

---

## 错误处理

本节点采用**全容错**设计，不会抛出异常中断工作流：

| 场景 | 处理方式 | 返回值 |
|------|---------|--------|
| `user_id` 为空 | 跳过加载 | `user_profile=None` |
| `user_id` 格式无效 | 记录 warning | `user_profile=None` + `warning` |
| 缓存/API 调用异常 | `except Exception` 捕获 | `user_profile=None` + `warning` |
| 预热失败 | 仅记录日志 | 不影响返回值 |

所有失败场景下工作流继续执行（匿名模式），后续步骤需检查 `user_profile is None`。

## UserProfile 数据模型

`user_profile` 在 `WorkflowState` 中类型为 `Optional[Dict[str, Any]]`，包含以下字段：

### basic_info（基础信息）

```python
{
    "age": 28,                        # 年龄（岁）
    "gender": "male",                 # 性别（male/female）
    "weight": 75.0,                   # 体重（kg）
    "height": 175.0,                  # 身高（cm）
    "training_level": "intermediate"  # 训练水平（beginner/intermediate/advanced）
}
```

### fitness_config（健身配置）

```python
{
    "training_frequency": 4,          # 每周训练次数
    "available_equipment": [          # 可用器械
        "哑铃", "杠铃", "卧推架", "龙门架"
    ],
    "recovery_capacity": 0.75         # 恢复能力评分（0-1）
}
```

### health_profile（健康档案）

```python
{
    "chronic_diseases": [             # 慢性病
        "腰椎间盘突出"
    ],
    "injury_history": [               # 损伤史
        {"type": "肩袖损伤", "date": "2023-06-15", "status": "已康复"}
    ],
    "contraindications": [            # 禁忌症
        "高强度脊柱负荷"
    ]
}
```

### 其他字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `nutrition_profile` | `Dict` | 营养档案（TDEE、宏量营养素） |
| `fitness_goals` | `Dict` | 健身目标（增肌、减脂、力量） |
| `strength_levels` | `Dict` | 力量水平（卧推、深蹲、硬拉） |

## 与后续步骤的数据流

### 输出到步骤2（会话记录存储）

步骤2 从 `state["user_id"]` 获取用户标识，与步骤1写入的 `user_profile` 无直接依赖，但两者共享同一个 `WorkflowState`。

### 输出到步骤3（会员权限检查）

- `state["user_profile"]` → 步骤3用于关联会员信息
- 步骤1异步预热的会员数据 → 步骤3执行时可能已在缓存中（减少 API 调用）

### 被后续 DAG 工具使用

步骤7（DAG 执行）中的工具直接从 `state["user_profile"]` 读取用户数据，无需重复调用 API：

```python
# DAG 工具中使用预加载的用户档案
user_profile = state.get("user_profile")
chronic_diseases = user_profile.get("health_profile", {}).get("chronic_diseases", [])
```
