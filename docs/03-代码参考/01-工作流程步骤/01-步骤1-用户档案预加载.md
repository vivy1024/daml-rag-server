## 概述

步骤1是DAML-RAG工作流程的第一步，负责从PHP后端（MySQL）预加载用户档案数据。这一步的关键特点是**0延迟返回**，因为用户档案在工作流程开始时就被加载到内存中，避免了DAG执行过程中的重复MCP调用。

### 在11步工作流程中的位置

```
步骤1: 预加载用户档案（0延迟）⭐ ← 当前
  ↓
步骤2: 会话记录存储
  ↓
步骤3: 会员权限检查
  ↓
...
```

### 核心类：BackendClient

```python
class BackendClient:
    """
    后端API客户端
    
    职责：
    - 从PHP后端获取用户档案
    - 获取会员权限信息
    - 保存会话记录
    - 自动重试机制
    """
    
    def __init__(self, config: BackendConfig):
        self.config = config
        self.client = httpx.AsyncClient(
            timeout=config.timeout,
            headers=config.get_headers()
        )
    
    async def get_user_profile(self, user_id: str) -> UserProfile:
        """
        获取用户档案（步骤1核心方法）
        
        Args:
            user_id: 用户ID
            
        Returns:
            UserProfile: 用户档案对象
            
        Raises:
            BackendAPIError: API调用失败
        """
        url = f"{self.config.base_url}/api/internal/user-profile/{user_id}"
        
        try:
            response = await self.client.get(url)
            response.raise_for_status()
            data = response.json()
            
            return UserProfile.from_api_response(data)
            
        except httpx.HTTPError as e:
            logger.error(f"获取用户档案失败: {e}")
            raise BackendAPIError(f"Failed to get user profile: {e}")
```

### 数据模型：UserProfile

```python
@dataclass
class UserProfile:
    """
    用户档案数据结构
    
    包含用户的所有基础信息，用于后续工具调用
    """
    user_id: str
    basic_info: Dict[str, Any]          # 基础信息（年龄、性别、体重、身高）
    nutrition_profile: Dict[str, Any]   # 营养档案（TDEE、宏量营养素）
    fitness_config: Dict[str, Any]      # 健身配置（训练频率、器械可用性）
    fitness_goals: Dict[str, Any]       # 健身目标（增肌、减脂、力量）
    strength_levels: Dict[str, Any]     # 力量水平（卧推、深蹲、硬拉）
    health_profile: Dict[str, Any]      # 健康档案（慢性病、损伤史）
    created_at: Optional[str] = None
    updated_at: Optional[str] = None
    
    @classmethod
    def from_api_response(cls, data: Dict[str, Any]) -> 'UserProfile':
        """从API响应创建UserProfile对象"""
        return cls(
            user_id=data.get('user_id', ''),
            basic_info=data.get('basic_info', {}),
            nutrition_profile=data.get('nutrition_profile', {}),
            fitness_config=data.get('fitness_config', {}),
            fitness_goals=data.get('fitness_goals', {}),
            strength_levels=data.get('strength_levels', {}),
            health_profile=data.get('health_profile', {}),
            created_at=data.get('created_at'),
            updated_at=data.get('updated_at'),
        )
```

## 关键特性

### 1. 0延迟返回

**原理**：用户档案在工作流程开始时就被加载到内存中，后续所有工具调用都直接从context获取，无需重复调用MCP工具。

```python
# ✅ 正确做法：预加载一次
user_profile = await backend_client.get_user_profile(user_id)  # 只调用1次
context["user_profile"] = user_profile

# 后续工具直接使用
tool1_result = await tool1(context)  # 0延迟
tool2_result = await tool2(context)  # 0延迟
tool3_result = await tool3(context)  # 0延迟

# ❌ 错误做法：每个工具都调用
tool1_result = await tool1(user_id)  # 调用get_user_profile
tool2_result = await tool2(user_id)  # 再次调用get_user_profile
tool3_result = await tool3(user_id)  # 又调用get_user_profile
```

**性能对比**：
- 预加载方式：1次API调用（~50ms）
- 重复调用方式：N次API调用（~50ms × N）

### 2. 自动重试机制

```python
class BackendClient:
    async def get_user_profile(self, user_id: str) -> UserProfile:
        """带自动重试的用户档案获取"""
        max_retries = self.config.max_retries
        
        for attempt in range(max_retries):
            try:
                response = await self.client.get(url)
                response.raise_for_status()
                return UserProfile.from_api_response(response.json())
                
            except httpx.HTTPError as e:
                if attempt < max_retries - 1:
                    logger.warning(f"重试获取用户档案 ({attempt + 1}/{max_retries})")
                    await asyncio.sleep(1 * (attempt + 1))  # 指数退避
                else:
                    raise BackendAPIError(f"获取用户档案失败: {e}")
```

### 3. 数据验证

```python
class UserProfile:
    def validate(self) -> bool:
        """验证用户档案数据完整性"""
        required_fields = [
            'basic_info',
            'fitness_config',
            'health_profile'
        ]
        
        for field in required_fields:
            if not getattr(self, field):
                logger.error(f"用户档案缺少必需字段: {field}")
                return False
        
        return True
```

## 错误处理

### 常见错误场景

#### 1. 用户不存在

```python
try:
    user_profile = await backend_client.get_user_profile(user_id)
except BackendAPIError as e:
    if "404" in str(e):
        return {
            "error": "用户不存在",
            "message": "请先完成用户注册"
        }
```

#### 2. API超时

```python
try:
    user_profile = await backend_client.get_user_profile(user_id)
except httpx.TimeoutException:
    logger.error("获取用户档案超时")
    # 降级策略：使用默认档案
    user_profile = UserProfile.get_default_profile(user_id)
```

#### 3. 数据不完整

```python
user_profile = await backend_client.get_user_profile(user_id)

if not user_profile.validate():
    logger.warning("用户档案数据不完整，使用默认值")
    user_profile = user_profile.fill_defaults()
```

## 性能优化

### 1. 缓存策略

```python
class BackendClient:
    def __init__(self):
        self.profile_cache = {}  # 用户档案缓存
        self.cache_ttl = 300     # 缓存5分钟
    
    async def get_user_profile(self, user_id: str) -> UserProfile:
        """带缓存的用户档案获取"""
        # 检查缓存
        if user_id in self.profile_cache:
            cached_profile, cached_time = self.profile_cache[user_id]
            if time.time() - cached_time < self.cache_ttl:
                logger.debug(f"从缓存返回用户档案: {user_id}")
                return cached_profile
        
        # 缓存未命中，从API获取
        profile = await self._fetch_user_profile(user_id)
        
        # 更新缓存
        self.profile_cache[user_id] = (profile, time.time())
        
        return profile
```

### 2. 并发控制

```python
class BackendClient:
    def __init__(self):
        self.semaphore = asyncio.Semaphore(10)  # 最多10个并发请求
    
    async def get_user_profile(self, user_id: str) -> UserProfile:
        """带并发控制的用户档案获取"""
        async with self.semaphore:
            return await self._fetch_user_profile(user_id)
```
