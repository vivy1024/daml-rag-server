## 概述

步骤5根据步骤4的复杂度分类结果，选择使用教师模型（DeepSeek）还是学生模型。当 `DUAL_MODEL_ENABLED=false` 时（当前默认），此步骤**快速跳过**，直接选择教师模型。

### 在工作流中的位置

```
步骤4: BGE复杂度分类
  ↓  complexity_level, _complexity_similarity
步骤5: 智能模型选择 ⭐ ← 当前
  ↓  输出 selected_model → 写入 WorkflowState
步骤6: Few-Shot检索
```

## 函数签名

```python
async def node_select_model(
    state: WorkflowState
) -> StateUpdate:
```

### 参数说明

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `state` | `WorkflowState` | ✅ | 当前工作流状态，包含 `request_id`、`complexity_level`、`_complexity_similarity`、`is_premium` |

### 返回值

```python
StateUpdate(updates={
    "selected_model": str,  # "teacher" | "student"
})
```

---

## 执行逻辑

### Feature Flag 快速跳过

```python
dual_model_enabled = os.getenv("DUAL_MODEL_ENABLED", "false").lower() == "true"
if not dual_model_enabled:
    return StateUpdate(updates={"selected_model": "teacher"})
```

> **当前生产环境 `DUAL_MODEL_ENABLED=false`**，此步骤总是返回 `teacher`（DeepSeek）。

### 三段式决策（双模型启用时）

```python
complexity_level = state.get("complexity_level", "simple")
similarity = state.get("_complexity_similarity", 0.0)
is_premium = state.get("is_premium", False)

# 复杂查询或高相似度 → 教师模型
if complexity_level == "complex" or similarity >= 0.7:
    model_choice = "teacher"
# 其他 → 学生模型
else:
    model_choice = "student"
```

| 条件 | 选择 | 说明 |
|------|------|------|
| `complexity_level == "complex"` | teacher | 复杂查询需要强模型 |
| `similarity >= 0.7` | teacher | 高相似度也用强模型 |
| 其他 | student | 简单/中等查询用轻量模型 |

> 注意：`is_premium` 当前未参与决策逻辑，但已从 state 中读取，预留扩展。
