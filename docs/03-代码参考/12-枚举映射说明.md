# 12 - 枚举映射说明

> 更新日期：2026-02-24 | 关联提交：`f40db2d` (Task 19 营养工具枚举对齐)

## 背景

系统中存在两套健身目标枚举值，分属不同架构层：

| 层级 | 枚举值 | 来源 |
|------|--------|------|
| 数据层（MySQL user_profiles） | `muscle_gain`, `weight_loss`, `fat_loss`, `strength` | Laravel 后端写入 |
| 工具层（MCP 营养工具 Literal） | `hypertrophy`, `fat_loss`, `maintenance`, `recomp` | DAML-RAG 工具接口 |

## 适配器

`task_executor.py` 的 `_get_primary_goal()` 方法内置 `_GOAL_NORMALIZE` 映射，负责在两层之间转换：

```python
_GOAL_NORMALIZE = {
    "weight_loss": "fat_loss",
    "muscle_gain": "hypertrophy",
}
```

## 保留映射清单

以下文件中的 `"muscle_gain"` / `"weight_loss"` 引用是**必需的**，因为它们处理的是数据层枚举：

| 文件 | 行号 | 用途 | 为什么保留 |
|------|------|------|-----------|
| `context/profile_injector.py` | 212, 278, 391 | 将档案目标值映射为中文显示文本 | 读取 MySQL 原始数据 |
| `dag/orchestrator.py` | 731 | 检查目标决定是否启用营养工具 | 读取用户档案原始值 |
| `fitness_adapter.py` | 181, 1295 | 规则引擎参数，按目标匹配训练偏好 | 匹配用户档案值 |
| `services/user_profile_integrator.py` | 614 | 目标对齐约束配置 | 匹配用户档案值 |
| `services/training_goal_recommender.py` | 363 | `["fat_loss", "weight_loss"]` 兼容判断 | 同时兼容新旧值 |

## 向量检索映射（不可删除）

以下映射用于将英文枚举转换为中文查询文本，供 Qdrant 向量检索使用（GTE-Large-zh 模型需要中文输入）：

| 文件 | 映射 | 用途 |
|------|------|------|
| `mcp_tools/exercise/intelligent_exercise_selector.py` | `difficulty_map`, `goal_map` | 枚举→中文，构建向量检索查询文本 |
| `mcp_tools/exercise/intelligent_exercise_selector.py` | `equipment_mapper` | 中英文器械名双向匹配 |

## 数据流

```
MySQL user_profiles
  │ fitness_goals.primary_goal = "muscle_gain"
  ▼
profile_injector / orchestrator / fitness_adapter
  │ 直接使用 "muscle_gain"（数据层枚举）
  ▼
task_executor._get_primary_goal()
  │ _GOAL_NORMALIZE: "muscle_gain" → "hypertrophy"
  ▼
MCP 营养工具 (Pydantic Literal 验证)
  │ 接受: "hypertrophy" | "fat_loss" | "maintenance" | "recomp"
  ▼
业务逻辑 (if fitness_goal == "hypertrophy": ...)
```

## 未来统一方案（可选）

如果要彻底消除双枚举，需要：
1. Laravel 后端 Migration：更新 `user_profiles.fitness_goals` 中的 `muscle_gain` → `hypertrophy`、`weight_loss` → `fat_loss`
2. 前端表单同步更新提交值
3. 删除 `_GOAL_NORMALIZE` 映射和上述保留映射中的旧值

当前不做迁移，通过适配器层兼容。
