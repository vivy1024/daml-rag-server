## 🎯 部署架构

### 单体容器架构

```
fitness_daml_rag 容器
  ├─ Python FastAPI服务 (端口8001)
  ├─ user-profile-stdio MCP服务器 (Stdio通信)
  └─ professional-fitness-coach-stdio MCP服务器 (Stdio通信)
```

**特点**：
- ✅ **零网络延迟**：MCP通过Stdio本地通信（最快）
- ✅ **纯镜像部署**：代码和依赖全部打包在镜像中
- ✅ **简单可靠**：单个容器，部署和运维简单
- ✅ **易于推送**：可推送到任何Docker镜像仓库

## 📋 部署前准备

### 1. 环境要求

**服务器配置**：
- CPU: 4核+ （推荐8核）
- 内存: 16GB+ （推荐32GB）
- 磁盘: 100GB+ SSD
- 操作系统: Linux (Ubuntu 20.04+/CentOS 7+) 或 Windows Server

**软件要求**：
- Docker: 20.10+
- Docker Compose: 2.0+

### 2. 克隆代码（首次部署）

```bash
git clone <你的仓库地址>
cd build_body/
```

### 3. 配置环境变量

创建 `.env` 文件：
```bash
# API密钥
DEEPSEEK_API_KEY=sk-xxxxx
OPENAI_API_KEY=sk-xxxxx

# 数据库密码（生产环境请修改）
MYSQL_ROOT_PASSWORD=strong_password_here
MYSQL_PASSWORD=strong_password_here
NEO4J_PASSWORD=strong_password_here
```

## 🚀 快速部署

### 方法1：使用部署脚本（推荐）

**Windows**:
```powershell
cd f:\build_body
.\scripts\deploy-production.ps1
```

**Linux/Mac**:
```bash
cd /path/to/build_body
chmod +x scripts/deploy-production.sh
./scripts/deploy-production.sh
```

脚本会自动：
1. 构建生产镜像（包含MCP服务器）
2. 标记版本号
3. 可选：推送到镜像仓库
4. 启动所有服务
5. 验证服务健康状态

---

### 方法2：手动部署

#### 步骤1：构建镜像

```bash
# 构建DAML-RAG生产镜像
docker-compose -f docker-compose.production.yml build daml-rag-server

# 查看镜像
docker images | grep fitness-daml-rag
```

**预期输出**：
```
fitness-daml-rag    latest    abc123def456    5 minutes ago    2.5GB
```

#### 步骤2：启动服务

```bash
# 启动所有服务
docker-compose -f docker-compose.production.yml up -d

# 查看服务状态
docker-compose -f docker-compose.production.yml ps
```

#### 步骤3：验证服务

```bash
# 等待服务启动
sleep 15

# 健康检查
curl http://localhost:8001/health

# 查看MCP模式
docker logs fitness_daml_rag 2>&1 | grep "mcp_mode"
# 预期输出：mcp_mode=real
```

## 🔧 运维管理

### 常用命令

**查看日志**：
```bash
# 实时查看
docker logs -f fitness_daml_rag

# 查看最近100行
docker logs --tail 100 fitness_daml_rag

# 搜索关键词
docker logs fitness_daml_rag 2>&1 | grep "ERROR"
```

**重启服务**：
```bash
# 重启单个服务
docker-compose -f docker-compose.production.yml restart daml-rag-server

# 重启所有服务
docker-compose -f docker-compose.production.yml restart
```

**停止服务**：
```bash
# 停止但保留数据
docker-compose -f docker-compose.production.yml down

# 停止并删除数据（危险！）
docker-compose -f docker-compose.production.yml down -v
```

**进入容器**：
```bash
docker exec -it fitness_daml_rag bash

# 在容器内检查MCP服务器
ls -lh /app/mcp-servers/*/build/
```

## ⚠️ 故障排查

### 问题1：服务启动失败

**症状**：容器启动后立即退出

**排查**：
```bash
# 查看完整日志
docker logs fitness_daml_rag

# 检查配置文件
docker exec fitness_daml_rag cat /app/config/mcp_registry.json
```

**常见原因**：
- 数据库连接失败（检查MySQL/Neo4j/Redis是否启动）
- MCP服务器构建失败（检查Node.js版本）
- 配置文件错误（检查mcp_registry.json）

---

### 问题2：MCP服务器未启动

**症状**：日志显示 `mcp_mode=mock` 而不是 `real`

**排查**：
```bash
# 检查MCP构建产物
docker exec fitness_daml_rag ls -lh /app/mcp-servers/*/build/

# 检查mcp_registry.json
docker exec fitness_daml_rag cat /app/config/mcp_registry.json
```

**解决**：确保 `mcp_registry.json` 存在且配置正确

---

### 问题3：内存不足

**症状**：容器频繁重启，日志显示OOM

**解决**：
```yaml
# docker-compose.production.yml
services:
  daml-rag-server:
    deploy:
      resources:
        limits:
          memory: 8G  # 增加内存限制
```

## 📈 性能优化

### 1. 预下载模型

在Dockerfile中添加：
```dockerfile
RUN python -c "from sentence_transformers import SentenceTransformer; \
    model = SentenceTransformer('BAAI/bge-m3'); \
    print('GTE-Large-zh model downloaded')"
```

### 2. 使用多阶段构建

```dockerfile
# 构建阶段
FROM node:20 AS mcp-builder
COPY user-profile-stdio /mcp/user-profile-stdio
RUN cd /mcp/user-profile-stdio && npm install && npm run build

# 运行阶段
FROM python:3.11-slim
COPY --from=mcp-builder /mcp/user-profile-stdio/build /app/mcp-servers/user-profile-stdio/build
```

### 3. 启用Redis缓存

确保环境变量配置正确：
```yaml
environment:
  REDIS_HOST: redis
  REDIS_PORT: 6379
  CACHE_TTL: 300  # 缓存5分钟
```
