## 📋 概述

本文档提供玉珍健身App完整的数据备份与恢复方案，涵盖MySQL、Neo4j、Qdrant三个核心数据存储系统。

### 备份内容

| 数据库 | 容器名 | 内容 | 典型大小 |
|------|------|------|------|
| **MySQL** | `fitness_mysql` | 用户数据、训练记录、营养日志 | ~4 MB |
| **Neo4j** | `fitness_neo4j` | 知识图谱（4329节点、171767关系） | ~13 MB |
| **Qdrant** | `fitness_qdrant` | 向量数据库（15823向量） | ~71 MB |
| **总计** | - | - | **~88 MB** |

## 🔧 详细备份流程

### 1. MySQL备份

#### 手动备份命令

**Windows PowerShell:**
```powershell
docker exec fitness_mysql mysqldump `
  -u root `
  -proot_password_2025 `
  --single-transaction `
  --quick `
  --lock-tables=false `
  fitness_app > ./backups/mysql-backup.sql
```

**Linux/macOS:**
```bash
docker exec fitness_mysql mysqldump \
  -u root \
  -proot_password_2025 \
  --single-transaction \
  --quick \
  --lock-tables=false \
  fitness_app > ./backups/mysql-backup.sql
```

#### 参数说明

| 参数 | 说明 |
|-----|------|
| `--single-transaction` | 保证数据一致性（InnoDB） |
| `--quick` | 不缓冲查询，直接导出 |
| `--lock-tables=false` | 不锁表（适合生产环境） |

#### 验证备份

```bash
# 检查文件大小
ls -lh ./backups/mysql-backup.sql

# 检查表数量
grep "CREATE TABLE" ./backups/mysql-backup.sql | wc -l

# 预期输出: 18
```

---

### 2. Neo4j备份

#### 手动备份命令

**步骤1: 在容器内创建压缩包**
```bash
docker exec fitness_neo4j tar czf /tmp/neo4j-backup.tar.gz /data
```

**步骤2: 复制到宿主机**
```bash
docker cp fitness_neo4j:/tmp/neo4j-backup.tar.gz ./backups/
```

**步骤3: 清理容器内临时文件**
```bash
docker exec fitness_neo4j rm /tmp/neo4j-backup.tar.gz
```

#### 验证备份

```bash
# 检查文件大小
ls -lh ./backups/neo4j-backup.tar.gz

# 查看压缩包内容
tar tzf ./backups/neo4j-backup.tar.gz | head -20

# 预期包含:
# data/databases/
# data/transactions/
# data/dbms/
```

## 🔄 详细恢复流程

### 1. MySQL恢复

#### 手动恢复命令

**Windows PowerShell:**
```powershell
Get-Content ./backups/mysql-backup.sql | docker exec -i fitness_mysql mysql -u root -proot_password_2025 fitness_app
```

**Linux/macOS:**
```bash
cat ./backups/mysql-backup.sql | docker exec -i fitness_mysql mysql -u root -proot_password_2025 fitness_app
```

#### 验证恢复

```bash
# 检查表数量
docker exec fitness_mysql mysql -u root -proot_password_2025 fitness_app -e "SHOW TABLES;"

# 检查用户数量
docker exec fitness_mysql mysql -u root -proot_password_2025 fitness_app -e "SELECT COUNT(*) FROM users;"
```

---

### 2. Neo4j恢复

#### 手动恢复命令（⚠️ 需要停止服务）

**步骤1: 停止Neo4j容器**
```bash
docker-compose stop neo4j
```

**步骤2: 复制备份到容器**
```bash
docker cp ./backups/neo4j-backup.tar.gz fitness_neo4j:/tmp/
```

**步骤3: 清空现有数据**
```bash
docker exec fitness_neo4j sh -c "rm -rf /data/*"
```

**步骤4: 解压备份**
```bash
docker exec fitness_neo4j tar xzf /tmp/neo4j-backup.tar.gz -C /
```

**步骤5: 清理临时文件**
```bash
docker exec fitness_neo4j rm /tmp/neo4j-backup.tar.gz
```

**步骤6: 启动Neo4j**
```bash
docker-compose start neo4j

# 等待启动（约30秒）
sleep 30
```

#### 验证恢复

```bash
# 检查节点数量
docker exec fitness_neo4j cypher-shell -u neo4j -ppassword \
  "MATCH (n) RETURN count(n) as count;"

# 预期输出: 4329

# 检查关系数量
docker exec fitness_neo4j cypher-shell -u neo4j -ppassword \
  "MATCH ()-[r]->() RETURN count(r) as count;"

# 预期输出: 171767
```

## 🎯 场景化指南

### 场景1: 生产环境日常备份

**频率**: 每天凌晨2:00

**方案**: 自动化定时任务

**Windows (任务计划程序):**
```powershell
# 创建定时任务
$action = New-ScheduledTaskAction -Execute "powershell.exe" `
  -Argument "-ExecutionPolicy Bypass -File F:\build_body\scripts\backup_all.ps1"

$trigger = New-ScheduledTaskTrigger -Daily -At "02:00"

Register-ScheduledTask -TaskName "BUILD_BODY_DailyBackup" `
  -Action $action -Trigger $trigger -Description "Daily database backup"
```

**Linux (crontab):**
```bash
# 编辑crontab
crontab -e

# 添加定时任务（每天凌晨2点）
0 2 * * * cd /path/to/build_body && bash scripts/backup_all.sh >> logs/backup.log 2>&1
```

### 场景2: 服务器迁移

**步骤概览:**
```
源服务器备份 → 上传云存储 → 下载到目标服务器 → 恢复
```

**详细流程:**

**1. 源服务器备份**
```bash
cd /path/to/build_body
bash scripts/backup_all.sh

# 输出: ./backups/20251108/
```

**2. 压缩并上传云存储**
```bash
# 压缩备份目录
tar czf backups-20251108.tar.gz backups/20251108/

# 上传到阿里云OSS
ossutil cp backups-20251108.tar.gz oss://your-bucket/backups/

# 或上传到七牛云
qshell rput your-bucket backups-20251108.tar.gz ./backups-20251108.tar.gz
```

**3. 目标服务器下载**
```bash
# 从OSS下载
ossutil cp oss://your-bucket/backups/backups-20251108.tar.gz ./

# 解压
tar xzf backups-20251108.tar.gz
```

**4. 目标服务器恢复**
```bash
# 确保Docker容器已启动
docker-compose up -d

# 等待服务启动
sleep 30

# 执行恢复
bash scripts/restore_all.sh 20251108
```

**5. 验证迁移**
```bash
# 检查MySQL
docker exec fitness_mysql mysql -u root -proot_password_2025 fitness_app -e "SELECT COUNT(*) FROM users;"

# 检查Neo4j
curl http://localhost:7474

# 检查Qdrant
curl http://localhost:6333/collections/fitness_kg

# 测试DAML-RAG Server API
curl http://localhost:8001/health
```

### 场景3: 灾难恢复（数据损坏）

**症状识别:**
- MySQL表损坏：`Table is marked as crashed`
- Neo4j无法启动：`Unable to start store`
- Qdrant数据丢失：`Collection not found`

**恢复步骤:**

**1. 立即停止所有服务**
```bash
docker-compose down
```

**2. 查看可用备份**
```bash
ls -lh backups/
# 选择最近的完整备份
```

**3. 启动容器（不启动应用）**
```bash
docker-compose up -d mysql neo4j qdrant
sleep 30
```

**4. 执行恢复**
```bash
bash scripts/restore_all.sh latest
```

**5. 验证数据完整性**
```bash
# MySQL数据验证
docker exec fitness_mysql mysql -u root -proot_password_2025 fitness_app -e "
  SELECT 
    'users' as table_name, COUNT(*) as row_count FROM users
  UNION ALL
  SELECT 'training_logs', COUNT(*) FROM training_logs
  UNION ALL
  SELECT 'nutrition_logs', COUNT(*) FROM nutrition_logs;
"

# Neo4j图结构验证
docker exec fitness_neo4j cypher-shell -u neo4j -ppassword "
  MATCH (e:Exercise)
  RETURN count(e) as exercise_count;
"

# Qdrant向量验证
curl http://localhost:6333/collections/fitness_kg
```

**6. 启动应用服务**
```bash
docker-compose up -d
```

## 🔍 故障排查

### 问题1: MySQL备份/恢复失败

**症状:**
```
mysqldump: [ERROR] mysqldump: unknown option '--single-transaction'.
```

**原因**: MySQL版本过低（< 5.0）

**解决:**
```bash
# 移除 --single-transaction 选项
docker exec fitness_mysql mysqldump -u root -proot_password_2025 fitness_app > backup.sql
```

---

### 问题2: Neo4j恢复后无法启动

**症状:**
```
Unable to start Neo4j. Unsupported version.
```

**原因**: Neo4j版本不匹配

**解决:**
```bash
# 检查备份的Neo4j版本
tar tzf neo4j-backup.tar.gz | grep version

# 确保容器版本一致
docker-compose.yml:
  neo4j:
    image: neo4j:5.15-community  # 必须与备份版本一致
```

---

### 问题3: Qdrant快照上传失败

**症状:**
```
Error: Request Entity Too Large (413)
```

**原因**: Qdrant配置的最大请求大小限制

**解决:**
```bash
# 方法A: 修改Qdrant配置
docker-compose.yml:
  qdrant:
    environment:
      - QDRANT__SERVICE__MAX_REQUEST_SIZE_MB=200

# 重启Qdrant
docker-compose restart qdrant

# 方法B: 直接恢复数据目录（需停止服务）
docker-compose stop qdrant
docker cp ./qdrant_data/ fitness_qdrant:/qdrant/storage/
docker-compose start qdrant
```

---

### 问题4: 备份占用空间过大

**症状:**
```
磁盘空间不足，无法创建备份
```

**解决:**
```bash
# 1. 清理旧备份（保留最近7天）
find ./backups/ -type d -mtime +7 -exec rm -rf {} \;

# 2. 压缩历史备份
cd backups/
for dir in 202511*; do
  tar czf ${dir}.tar.gz ${dir}/
  rm -rf ${dir}/
done

# 3. 上传到云存储后删除本地备份
ossutil cp -r ./backups/ oss://your-bucket/backups/
rm -rf ./backups/202511*
```

## 🚨 重要提醒

### ⚠️ 安全警告

1. **密码安全**: 
   - 备份脚本中的数据库密码是明文
   - 生产环境应使用环境变量或密钥管理服务
   
   ```bash
   # 使用环境变量
   export MYSQL_ROOT_PASSWORD="your_password"
   export NEO4J_PASSWORD="your_password"
   
   # 修改脚本读取环境变量
   MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASSWORD:-root_password_2025}
   ```

2. **备份加密**:
   ```bash
   # 加密备份文件
   tar czf - backups/20251108/ | openssl enc -aes-256-cbc -salt -out backups-20251108-encrypted.tar.gz.enc
   
   # 解密
   openssl enc -aes-256-cbc -d -in backups-20251108-encrypted.tar.gz.enc | tar xz
   ```

3. **访问控制**:
   - 备份文件包含敏感数据，限制访问权限
   ```bash
   chmod 700 backups/
   chmod 600 backups/*/*.sql
   ```
