BUILD_BODY采用**三层部署架构**：

```
┌─────────────────────────────────────────────────────────────┐
│                    第1层：Docker镜像                          │
│  ✅ 已包含：代码 + 环境 + GTE-Large-zh模型 (~5GB)                    │
│  📦 推送到：Docker Hub / 阿里云容器镜像                        │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                 第2层：数据库服务（Empty）                     │
│  MySQL + Redis + Neo4j + Qdrant                             │
│  🔧 Neo4j初始状态：空数据库，无节点无关系                      │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│              第3层：知识图谱数据导入（关键步骤）                │
│  方案A：使用本地备份恢复 ⭐ 推荐                              │
```

## 🚢 第一步：Docker镜像推送方案

### 方案A：推送到Docker Hub（推荐）

#### 1. 本地构建并测试镜像

```bash
# 1. 构建所有服务镜像
cd f:/build_body
docker-compose build

# 2. 验证镜像是否成功构建
docker images | grep fitness

# 预期看到以下镜像：
# build_body-nginx_v2
# build_body-php_v2
# build_body-fitness_daml_rag
```

#### 2. 给镜像打标签

```bash
# 替换 YOUR_DOCKERHUB_USERNAME 为你的Docker Hub用户名

# PHP后端镜像
docker tag build_body-php_v2:latest YOUR_DOCKERHUB_USERNAME/fitness-php-backend:v2.0.0
docker tag build_body-php_v2:latest YOUR_DOCKERHUB_USERNAME/fitness-php-backend:latest

# Nginx服务器镜像
docker tag build_body-nginx_v2:latest YOUR_DOCKERHUB_USERNAME/fitness-nginx:v2.0.0
docker tag build_body-nginx_v2:latest YOUR_DOCKERHUB_USERNAME/fitness-nginx:latest

# DAML-RAG Server AI服务镜像（包含GTE-Large-zh模型，约5GB）
docker tag build_body-fitness_daml_rag:latest YOUR_DOCKERHUB_USERNAME/fitness-mcp-ai:v2.0.0
docker tag build_body-fitness_daml_rag:latest YOUR_DOCKERHUB_USERNAME/fitness-mcp-ai:latest
```

#### 3. 登录Docker Hub

```bash
docker login
# 输入用户名和密码
```

#### 4. 推送镜像到Docker Hub

```bash
# 推送PHP后端镜像（约500MB）
docker push YOUR_DOCKERHUB_USERNAME/fitness-php-backend:v2.0.0
docker push YOUR_DOCKERHUB_USERNAME/fitness-php-backend:latest

# 推送Nginx镜像（约50MB）
docker push YOUR_DOCKERHUB_USERNAME/fitness-nginx:v2.0.0
docker push YOUR_DOCKERHUB_USERNAME/fitness-nginx:latest

# 推送DAML-RAG Server AI服务镜像（约5GB，需要较长时间）
docker push YOUR_DOCKERHUB_USERNAME/fitness-mcp-ai:v2.0.0
docker push YOUR_DOCKERHUB_USERNAME/fitness-mcp-ai:latest
```

**⏱️ 预计耗时**：
- PHP后端：3-10分钟
- Nginx：1-3分钟
- DAML-RAG Server AI服务：30-90分钟（取决于网速）

## 📊 第四步：导入知识图谱数据（核心步骤）

### 为什么需要这一步？

Docker镜像**不包含**Neo4j数据，因为：
1. Neo4j数据是动态生成的，不适合打包到镜像
2. 数据会随时间增长变化（用户数据、训练记录等）
3. 镜像会非常大（>10GB）且难以维护

**因此必须在服务器上导入数据！有两种方式：**

---

### ⭐ 方案A：使用本地备份恢复（推荐，最快！）

**适用场景**：本地已有完整数据和备份  
**优点**：速度快（5-10分钟）、数据完全一致、无需重新执行导入脚本  
**前提条件**：本地已执行备份（`f:\build_body\backups\20251106\`）

#### 1. 上传备份文件到服务器

```bash
# 在本地Windows上执行（PowerShell或CMD）
# 上传Neo4j备份（13.2 MB）
scp f:\build_body\backups\20251106\neo4j-backup-20251106_133638.tar.gz username@your-server:/tmp/

# 上传MySQL备份（4.0 MB）
scp f:\build_body\backups\20251106\mysql-fitness_app-20251106_133638.sql username@your-server:/tmp/
```

**⏱️ 上传时间**：取决于网速
- 100Mbps网络：约2-3分钟
- 10Mbps网络：约20-30分钟

---

#### 2. 在服务器上恢复Neo4j

```bash
# SSH登录到服务器
ssh username@your-server

# 恢复Neo4j数据
# 第1步：复制备份文件到Neo4j容器
docker cp /tmp/neo4j-backup-20251106_133638.tar.gz fitness_neo4j:/tmp/

# 第2步：停止Neo4j
docker compose stop neo4j

# 第3步：清空现有数据（如果有）
docker exec fitness_neo4j rm -rf /data/*

# 第4步：解压备份
docker exec fitness_neo4j tar xzf /tmp/neo4j-backup-20251106_133638.tar.gz -C /

# 第5步：清理临时文件
docker exec fitness_neo4j rm /tmp/neo4j-backup-20251106_133638.tar.gz

# 第6步：启动Neo4j
docker compose start neo4j

# 第7步：等待Neo4j启动（约30秒）
sleep 30

# 第8步：验证数据
docker exec fitness_neo4j cypher-shell -u neo4j -p fitness123 "MATCH (n) RETURN count(n);"
```

**预期结果**：应该看到 `4329` 个节点

---

#### 3. 在服务器上恢复MySQL

```bash
# 恢复MySQL数据
cat /tmp/mysql-fitness_app-20251106_133638.sql | docker exec -i fitness_mysql mysql -u root -proot_password_2025

# 验证数据
docker exec fitness_mysql mysql -u root -proot_password_2025 -e "USE fitness_app; SHOW TABLES;"
```

**预期结果**：应该看到所有业务表（users、workout_logs等）

---

#### 4. 验证完整性

```bash
# 验证Neo4j节点和关系数量
docker exec fitness_neo4j cypher-shell -u neo4j -p fitness123 << 'EOF'
MATCH (n) RETURN count(n) as total_nodes;
MATCH ()-[r]->() RETURN count(r) as total_relationships;
EOF
```

**预期结果**：
- 总节点数：4,329
- 总关系数：171,767

#### 5. 清理临时文件

```bash

rm /tmp/mysql-fitness_app-*.sql
```

## ⚠️ 常见问题与解决方案

### Q1: 镜像推送太慢怎么办？

**A**: 使用阿里云容器镜像服务
```bash
# 国内推送速度更快
docker login --username=YOUR_ALIYUN_USERNAME registry.cn-hangzhou.aliyuncs.com
```

---

### Q2: 服务器拉取镜像超时？

**A**: 配置镜像加速器
```bash
# 创建daemon.json
sudo nano /etc/docker/daemon.json

# 添加以下内容
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://dockerproxy.com",
    "https://hub-mirror.c.163.com"
  ]
}

# 重启Docker
sudo systemctl daemon-reload
sudo systemctl restart docker
```

---

### Q3: Neo4j连接失败？

**A**: 检查密码配置
```bash
# 方案A：进入容器检查Neo4j密码
docker exec fitness_neo4j cypher-shell -u neo4j -p fitness123 "RETURN 1;"

# 方案B：修改脚本密码
# 将所有脚本中的 password 改为 fitness123

# 方案C：修改Neo4j密码为脚本默认值
docker exec fitness_neo4j cypher-shell -u neo4j -p fitness123 "ALTER USER neo4j SET PASSWORD 'password';"
```

---

### Q4: 导入脚本失败：找不到数据文件？

**A**: 检查文件是否上传到服务器
```bash
# 检查SQLite数据库
docker exec fitness_mcp_meta_learning ls -lh /app/data/knowledge_graph_mvp.db

# 检查营养数据
docker exec fitness_mcp_meta_learning ls -lh /app/mcp-servers/archive/data/

# 如果文件不存在，从本地上传
```
