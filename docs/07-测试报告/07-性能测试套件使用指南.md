## 🚀 快速开始

### 前置条件

1. **Docker环境运行**
   ```bash
   # 检查服务状态
   docker-compose ps
   
   # 确保fitness_daml_rag容器正在运行
   docker-compose up -d fitness_daml_rag
   ```

2. **API可访问**
   ```bash
   # 测试API连接
   curl http://localhost:8001/health
   ```

### 运行测试

```bash
# 方式1: 使用便捷脚本（推荐）
./scripts/run_performance_tests.sh all

# 方式2: 直接使用pytest
docker exec fitness_daml_rag pytest tests/performance/ -v

# 方式3: 运行特定测试
docker exec fitness_daml_rag pytest tests/performance/test_e2e_performance.py -v
```

## 🧪 测试类型

### 1. 端到端性能测试

**文件**: `test_e2e_performance.py`

**测试内容**:
- 顺序性能测试（工作流总耗时和TTFB）
- 并发性能测试（QPS）
- 缓存命中率测试
- 完整端到端测试

**运行方式**:
```bash
# 运行所有端到端测试
docker exec fitness_daml_rag pytest tests/performance/test_e2e_performance.py -v

# 运行单个测试
docker exec fitness_daml_rag pytest tests/performance/test_e2e_performance.py::test_sequential_performance -v

# 运行完整测试并生成报告
docker exec fitness_daml_rag pytest tests/performance/test_e2e_performance.py::test_full_e2e_performance -v
```

**测试用例**:
- `test_sequential_performance()` - 顺序性能测试
- `test_concurrent_performance()` - 并发性能测试
- `test_cache_hit_rate()` - 缓存命中率测试
- `test_full_e2e_performance()` - 完整端到端测试

### 2. 压力测试

**文件**: `test_stress_test.py`

**测试内容**:
- 持续负载测试（30秒，50 QPS）
- 突发负载测试（5次突发，每次100请求）
- 系统资源监控（CPU、内存）

**运行方式**:
```bash
# 运行所有压力测试
docker exec fitness_daml_rag pytest tests/performance/test_stress_test.py -v -m slow

# 运行持续负载测试
docker exec fitness_daml_rag pytest tests/performance/test_stress_test.py::test_sustained_load -v

# 运行完整压力测试
docker exec fitness_daml_rag pytest tests/performance/test_stress_test.py::test_full_stress_test -v
```

**测试用例**:
- `test_sustained_load()` - 持续负载测试
- `test_burst_load()` - 突发负载测试
- `test_full_stress_test()` - 完整压力测试

### 3. 快速验证测试

**文件**: `test_quick_validation.py`

**测试内容**:
- API健康检查
- 简单查询测试
- 小规模并发测试（5个请求）

**运行方式**:
```bash
# 运行快速验证测试
docker exec fitness_daml_rag pytest tests/performance/test_quick_validation.py -v
```

**用途**:
- 快速验证测试基础设施
- 确保API可访问
- 验证基本功能正常

## 🔧 测试配置

### 修改测试参数

编辑测试文件中的配置常量：

```python
# test_e2e_performance.py
API_BASE_URL = "http://localhost:8001"  # API地址
TEST_USER_ID = "test_user_001"          # 测试用户ID
TEST_QUERIES = [...]                     # 测试查询列表

# test_stress_test.py
API_BASE_URL = "http://localhost:8001"
TEST_USER_ID = "stress_test_user"
```

### 调整性能目标

修改 `test_e2e_performance.py` 中的断言：

```python
# 工作流总耗时目标
assert avg_response_time < 30.0  # 修改为你的目标值

# TTFB目标
assert avg_ttfb < 5.0  # 修改为你的目标值

# QPS目标
assert qps >= 200  # 修改为你的目标值

# 缓存命中率目标
assert cache_hit_rate >= 0.8  # 修改为你的目标值
```

### 调整测试规模

```python
# 顺序测试请求数
result = await run_sequential_test(num_requests=10)  # 修改数量

# 并发测试配置
result = await run_concurrent_test(
    num_requests=100,  # 总请求数
    concurrency=20     # 并发数
)

# 缓存测试请求数
result = await run_cache_test(num_requests=20)  # 修改数量

# 持续负载测试配置
metrics = await sustained_load_test(
    duration_seconds=30,  # 测试时长
    target_qps=50         # 目标QPS
)

# 突发负载测试配置
metrics = await burst_load_test(
    burst_size=100,       # 每次突发请求数
    num_bursts=5,         # 突发次数
    burst_interval=10     # 突发间隔（秒）
)
```

## 🔍 结果分析

### 性能指标解读

#### 响应时间指标

- **平均值（avg）**: 所有请求的平均响应时间
- **中位数（median）**: 50%的请求响应时间低于此值
- **P95**: 95%的请求响应时间低于此值
- **P99**: 99%的请求响应时间低于此值
- **最小值（min）**: 最快的响应时间
- **最大值（max）**: 最慢的响应时间

#### TTFB指标

- **TTFB（Time To First Byte）**: 从发送请求到收到第一个字节的时间
- 反映系统的初始响应速度
- 对用户体验影响最大

#### 吞吐量指标

- **QPS（Queries Per Second）**: 每秒处理的查询数
- 反映系统的并发处理能力
- 越高越好

#### 缓存指标

- **命中率（hit_rate）**: 缓存命中次数 / 总请求次数
- 反映缓存系统的有效性
- 目标: >= 80%

#### 系统资源指标

- **CPU使用率**: 系统CPU占用百分比
- **内存使用率**: 系统内存占用百分比
- 反映系统负载情况

### 性能目标对比

| 指标 | 目标值 | 如何判断 |
|------|--------|---------|
| 工作流总耗时 | < 30秒 | 查看 `response_time.avg` |
| TTFB | < 5秒 | 查看 `ttfb.avg` |
| QPS | >= 200 | 查看 `qps` |
| 缓存命中率 | >= 80% | 查看 `cache.hit_rate` |

### 问题诊断

#### 响应时间过长

**可能原因**:
- 数据库查询慢
- LLM调用超时
- 缓存未命中
- 网络延迟

**诊断方法**:
```bash
# 查看性能监控日志
docker exec fitness_daml_rag tail -f logs/performance.log

# 查看步骤耗时
# 在报告中查看 steps 字段
```

#### QPS不达标

**可能原因**:
- 并发限制过低
- 连接池不足
- 系统资源瓶颈

**诊断方法**:
```bash
# 查看系统资源
docker stats fitness_daml_rag

# 查看连接池状态
# 检查 connection_pool 配置
```

#### 缓存命中率低

**可能原因**:
- TTL设置过短
- 缓存容量不足
- Redis不可用

**诊断方法**:
```bash
# 检查Redis状态
docker exec fitness_redis redis-cli ping

# 查看缓存配置
cat config/performance_optimization.yaml
```

## 🐛 故障排查

### 常见问题

#### 1. 服务未启动

**症状**: 测试失败，提示连接错误

**解决方案**:
```bash
# 检查服务状态
docker-compose ps fitness_daml_rag

# 启动服务
docker-compose up -d fitness_daml_rag

# 查看日志
docker-compose logs fitness_daml_rag
```

#### 2. API不可访问

**症状**: 测试失败，HTTP 404或500错误

**解决方案**:
```bash
# 测试连接
curl http://localhost:8001/health

# 检查端口映射
docker-compose ps

# 查看API日志
docker-compose logs -f fitness_daml_rag
```

#### 3. 超时错误

**症状**: 测试超时，部分请求失败

**解决方案**:
- 增加测试超时时间
- 检查系统资源（CPU、内存）
- 优化慢查询
- 检查网络连接

#### 4. 缓存命中率低

**症状**: 缓存命中率低于预期

**解决方案**:
```bash
# 检查Redis服务
docker exec fitness_redis redis-cli ping

# 验证缓存配置
cat config/performance_optimization.yaml

# 检查缓存日志
docker exec fitness_daml_rag grep "cache" logs/performance.log
```

### 查看详细日志

```bash
# 查看测试输出
docker exec fitness_daml_rag pytest tests/performance/test_e2e_performance.py -v -s

# 查看服务日志
docker-compose logs -f fitness_daml_rag

# 查看性能监控日志
docker exec fitness_daml_rag tail -f logs/performance.log

# 查看错误日志
docker exec fitness_daml_rag tail -f logs/error.log
```

## 📈 持续集成

### 在CI/CD中运行

#### GitHub Actions示例

```yaml
# .github/workflows/performance-test.yml
name: Performance Tests

on:
  push:
    branches: [ main ]
  schedule:
    - cron: '0 0 * * *'  # 每天运行

jobs:
  performance-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      
      - name: Start services
        run: docker-compose up -d
      
      - name: Wait for services
        run: sleep 30
      
      - name: Run performance tests
        run: |
          docker exec fitness_daml_rag pytest tests/performance/test_e2e_performance.py -v
      
      - name: Upload reports
        uses: actions/upload-artifact@v2
        with:
          name: performance-reports
          path: tests/performance/*.json
      
      - name: Check performance targets
        run: |
          # 解析报告并检查是否达标
          python scripts/check_performance_targets.py
```

### 定期执行

```bash
# 使用cron定期执行（Linux）
# 编辑crontab
crontab -e

# 添加定时任务（每天凌晨2点执行）
0 2 * * * cd /path/to/project && ./scripts/run_performance_tests.sh all >> /var/log/performance_test.log 2>&1
```
