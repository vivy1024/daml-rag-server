## 已知问题

### 问题1: 旧日志时间戳被拒绝

**现象**: Promtail启动时尝试采集旧日志，但被Loki拒绝

**错误信息**:
```
level=error caller=client.go:430 msg="final error sending batch" status=400 
error="entry has timestamp too old: 2025-12-16T09:51:01Z, oldest acceptable timestamp is: 2025-12-16T13:04:54Z"
```

**原因**: Loki配置了`reject_old_samples_max_age: 168h`（7天），超过7天的日志会被拒绝

**影响**: 不影响新日志的采集，只是历史日志无法导入

**解决方案**: 
1. 如果需要导入历史日志，可以临时调整Loki的`reject_old_samples_max_age`配置
2. 或者清理旧日志文件，只保留最近7天的日志

---

### 问题2: 测试日志未立即出现在查询结果中

**现象**: 追加到日志文件的测试日志没有立即出现在Loki查询结果中

**可能原因**:
1. Promtail的批量发送延迟（默认1秒）
2. Loki的索引延迟
3. 查询时间范围不准确

**影响**: 轻微，日志会在几秒到几十秒内出现

**解决方案**: 
1. 等待10-30秒后再查询
2. 使用更宽的时间范围查询
3. 检查Promtail的`batchwait`和`batchsize`配置

### B. 配置文件参考

**Promtail配置关键部分**:
```yaml
scrape_configs:
  - job_name: daml-rag-files
    static_configs:
      - targets:
          - localhost
        labels:
          job: daml-rag-files
          source: file
          __path__: /app/logs/daml-rag-*.log
    
    pipeline_stages:
      - regex:
          expression: '^(?P<timestamp>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3}) - (?P<logger>\S+) - (?P<level>\S+) - (?P<message>.*)'
      - labels:
          level:
          logger:
      - timestamp:
          source: timestamp
          format: '2006-01-02 15:04:05,000'
```

**Loki配置关键部分**:
```yaml
limits_config:
  retention_period: 720h  # 30天
  reject_old_samples: true
  reject_old_samples_max_age: 168h  # 7天
  ingestion_rate_mb: 10
  ingestion_burst_size_mb: 20
```
