## 概述

DAML-RAG系统使用多种数据库来支持不同的数据存储和检索需求：
- **Neo4j**: 图数据库，存储健身知识图谱
- **Qdrant**: 向量数据库，存储语义向量
- **MySQL**: 关系数据库，存储用户数据和训练记录
- **Redis**: 缓存数据库，提供高速缓存服务

本文档重点介绍Neo4j和Qdrant的数据结构，这两个数据库是DAML-RAG三层检索架构的核心。

### 核心节点详解

#### Exercise节点（1,603个，34字段）

Exercise节点是系统中最重要的节点类型，包含完整的动作信息：

**基础信息**：
- `id`: 节点唯一标识
- `name_zh`: 中文名称（如："哑铃弯举"）
- `name_en`: 英文名称（如："Dumbbell Curl"）
- `difficulty`: 难度（新手/中级/高级）
- `equipment_zh`: 中文器材名
- `equipment_en`: 英文器材名

**训练参数**：
- `rep_range`: 次数范围（如："8-15"）
- `set_range`: 组数范围（如："2-3"）
- `rest_period`: 休息时间（如："60-90秒"）
- `intensity_percentage`: 强度百分比（如："50-60%"）

**技术细节**：
- `force`: 力量类型（如："拉力"）
- `mechanic`: 力学特性（如："单关节动作"）
- `grips`: 握法（如："反手握"）
- `correct_steps_zh`: 正确步骤
- `technique_focus`: 技术要点

**安全信息**：
- `safety_level`: 安全等级（LOW_RISK/MEDIUM_RISK/HIGH_RISK）
- `safety_pre_check`: 训练前检查
- `safety_during`: 训练中注意事项
- `safety_warning_signs`: 危险信号

**v5.1.0新增字段**：
- `kinetic_chain_type`: 运动链类型（open_chain/closed_chain/mixed）
- `technique_checkpoints`: 技术检查点（JSON格式）
- `rom_requirements`: 关节活动度要求（JSON格式）

#### Muscle节点（53个，16字段）

Muscle节点包含完整的肌肉训练科学数据：

**基础信息**：
- `id`: 节点唯一标识（如："m010"）
- `name_zh`: 肌群名称（如："肱二头肌"）
- `name_en`: 英文名称（如："Biceps Brachii"）
- `category`: 分类（primary/secondary）

**训练科学数据**：
- `training_frequency`: 训练频率（如："2-3次/周"）
- `recovery_time`: 恢复时间（如："48小时"）
- `movement_patterns`: 动作模式列表（如：["弯举", "引体向上"]）
- `function`: 功能描述列表（如：["肘关节屈曲", "前臂旋后"]）
- `synergy_partners`: 协同肌群列表（如：["肱肌", "肱桡肌"]）
- `antagonist_partners`: 对抗肌群列表（如：["肱三头肌"]）
- `group`: 肌群分组（如："arm", "chest", "back"）

**v5.2.0新增训练量标准**（基于Mike Israetel的研究）：
- `mev`: 最小有效训练量（Minimum Effective Volume，组/周）
- `mav`: 最大适应训练量（Maximum Adaptive Volume，组/周）
- `mrv`: 最大可恢复训练量（Maximum Recoverable Volume，组/周）
- `mv`: 维持训练量（Maintenance Volume，组/周）
- `optimal_frequency`: 最佳训练频率（次/周）

**训练量标准说明**：
- MEV：产生训练效果的最小训练量
- MAV：产生最佳训练效果的训练量
- MRV：身体能够恢复的最大训练量
- MV：维持当前肌肉量的训练量
- 训练量应在MEV和MRV之间，最佳范围是MAV附近

#### StrengthStandard节点（360个）✅ v5.2新增

StrengthStandard节点存储力量标准数据，用于评估用户的力量水平：

**完整字段**：
- `id`: 标准ID（如："bench_press_male_70kg_beginner"）
- `exercise_name`: 动作名称（如："卧推"）
- `exercise_id`: 对应的Exercise节点ID
- `gender`: 性别（male/female）
- `bodyweight_kg`: 体重（kg）
- `level`: 力量水平（beginner/intermediate/advanced/elite）
- `weight_kg`: 该水平应达到的重量（kg）

**覆盖范围**：
- 主要动作：深蹲、卧推、硬拉、推举、引体向上等
- 性别：男性、女性
- 体重范围：50-120kg
- 力量水平：初学者、中级、高级、精英

**用途**：
- 评估用户当前力量水平
- 计算训练重量（如：增肌训练使用60-80% 1RM）
- 设定力量目标
- 跟踪力量进步

#### WorkoutProgram节点（8个）✅ v5.2新增

WorkoutProgram节点存储训练计划模板：

**完整字段**：
- `id`: 计划ID（如："beginner_full_body"）
- `name`: 计划名称（如："初学者全身训练"）
- `goal`: 训练目标（增肌/减脂/力量/耐力）
- `training_split`: 训练分化（全身/上下肢/推拉腿/部位）
- `training_days_per_week`: 每周训练天数
- `duration_weeks`: 计划持续周数
- `description`: 计划描述
- `target_level`: 目标水平（beginner/intermediate/advanced）

**关系**：
- `INCLUDES_EXERCISE`: 连接到Exercise节点（包含的动作）
- `TARGETS_MUSCLE`: 连接到Muscle节点（目标肌群）
- `SUITABLE_FOR`: 连接到TrainingLevel节点（适合的水平）
- `RECOMMENDED_FOR`: 连接到TrainingGoal节点（推荐的目标）

**8个训练计划模板**：
1. 初学者全身训练（3天/周）
2. 中级上下肢分化（4天/周）
3. 高级推拉腿分化（6天/周）
4. 增肌专项计划（4天/周）
5. 减脂专项计划（5天/周）
6. 力量专项计划（4天/周）
7. 耐力专项计划（3天/周）
8. 混合目标计划（5天/周）

#### RehabilitationPhase节点（3个）

RehabilitationPhase节点定义康复阶段：

**节点属性**：
- `phase_id`: 阶段ID（acute/subacute/recovery）
- `name_zh`: 中文名称
- `name_en`: 英文名称
- `duration_days`: 持续天数
- `goals`: 康复目标（JSON数组）
- `allowed_activities`: 允许的活动（JSON数组）
- `contraindicated_activities`: 禁忌活动（JSON数组）
- `description`: 阶段描述

**三个康复阶段**：
1. **急性期（acute）**：持续7天，目标是减轻疼痛、控制炎症
2. **亚急性期（subacute）**：持续14天，目标是恢复活动度、增强肌力
3. **恢复期（recovery）**：持续30天，目标是恢复运动表现、预防再次受伤

### 关键关系详解

#### TARGETS关系（3,965个）

TARGETS关系连接Exercise和Muscle，表示动作对肌肉的训练效果：

- **TARGETS_PRIMARY**（1,603个）：主要目标肌群
- **TARGETS_SECONDARY**（2,362个）：次要目标肌群

**覆盖率**：100%的Exercise都有TARGETS关系

#### CONTRAINDICATED_FOR关系（3,726个）✅ v5.1增强

CONTRAINDICATED_FOR关系连接Exercise和InjuryType，表示动作对特定损伤的禁忌关系：

**关系属性**：
- `severity`: 严重程度分级（absolute/relative/caution）
  - **绝对禁忌 (Absolute Contraindication)** 🚫：任何情况下都不应进行的动作
    - 示例：肩袖损伤患者做过头推举，腰椎间盘突出患者做硬拉
  - **相对禁忌 (Relative Contraindication)** ⚠️：在特定条件下可以进行的动作
    - 示例：恢复期肩袖损伤患者做轻负荷肩推，轻度下背部疼痛患者做浅蹲
  - **谨慎使用 (Use with Caution)** 💡：可以进行但需要特别注意的动作
    - 示例：老年人做跳跃动作，高血压患者做大重量训练
- `reason`: 禁忌原因（生物力学解释）
- `created_at`: 创建时间
- `source`: 数据来源 (expert_discussion_v2)

**损伤类型覆盖**：
- **Phase 1 核心损伤**（已完成）：6个损伤类型，1,882个关系
  - 肩袖损伤：255个关系（绝对禁忌）
  - 肩峰撞击：228个关系（绝对禁忌）
  - 髌骨软化症：405个关系（绝对禁忌）
  - 腰椎间盘突出：334个关系（绝对禁忌）
  - 下背部疼痛：316个关系（相对禁忌）
  - 膝盖受伤：344个关系（相对禁忌）
- **Phase 2 重要损伤**（已完成）：4个损伤类型，906个关系
  - 前交叉韧带损伤：299个关系（绝对禁忌）
  - 高尔夫球肘：272个关系（绝对禁忌）
  - 网球肘：261个关系（绝对禁忌）
  - 颈椎病：74个关系（绝对禁忌）
- **Phase 3 补充损伤**（已完成）：4个损伤类型，938个关系
  - 髂胫束综合征：304个关系（相对禁忌）
  - 跟腱炎：289个关系（绝对禁忌）
  - 足底筋膜炎：210个关系（相对禁忌）
  - 腕管综合征：135个关系（绝对禁忌）

**查询示例**：
```cypher
// 查询肩袖损伤的绝对禁忌动作
MATCH (e:Exercise)-[r:CONTRAINDICATED_FOR {severity: 'absolute'}]->(i:InjuryType {name: '肩袖损伤'})
RETURN e.name_zh, r.reason

// 查询某个动作的所有禁忌症
MATCH (e:Exercise {name_zh: '杠铃深蹲'})-[r:CONTRAINDICATED_FOR]->(i:InjuryType)
RETURN i.name, r.severity, r.reason
```

## Qdrant向量数据库

### 核心统计数据

Qdrant存储语义向量，支持Layer 1的向量语义检索：

**集合统计**：
- **training_knowledge**：43个向量（训练知识）✅ v5.2更新
- **fitness_exercises_v2**：1,596个向量（健身动作）
- **food_nutrition_vector**：1,851个向量（食物营养）

**向量参数**：
- **模型**：BGE-M3
- **维度**：1024维
- **语言**：支持中英文

### 向量集合详解

#### training_knowledge集合（43个向量）✅ v5.2更新

存储训练相关的知识文档，支持语义检索：

**向量来源**：
1. **训练决策树**（recommendation_decision_tree.md）
   - 训练分化选择逻辑
   - 训练频率建议
   - 训练周期计算
   - 训练量分配策略

2. **用户档案分析逻辑**（user_profile_analysis_logic.md）
   - 用户水平评估
   - 目标分析
   - 个性化建议生成

**向量化策略**：
- 分块大小：512 tokens
- 重叠：50 tokens
- 元数据：source_file, chunk_index, text

**用途**：
- LLM决策时检索相关训练知识
- 生成训练计划时参考科学依据
- 回答用户训练相关问题

#### fitness_exercises_v2集合

存储Exercise节点的语义向量：
- 基于Exercise的描述生成
- 支持自然语言查询动作
- 与Neo4j的Exercise节点一一对应

#### food_nutrition_vector集合

存储Food节点的语义向量：
- 基于Food的营养信息生成
- 支持自然语言查询食物
- 与Neo4j的Food节点一一对应

### 向量检索流程

```
用户查询
    ↓
BGE-M3编码（1024维向量）
    ↓
Qdrant相似度搜索
    ↓
返回Top-K相似向量
    ↓
映射到Neo4j节点ID
    ↓
Neo4j图查询获取完整信息
```

## 数据清洗与微调架构规划

### 概述

DAML-RAG系统规划了完整的数据清洗与微调架构，旨在通过持续的数据积累和模型微调，不断提升系统的专业水平和响应质量。

### 数据清洗流程

#### 触发条件

数据清洗流程将在以下条件触发：
- **定期触发**：每周日凌晨2:00执行
- **对话量触发**：对话量达到1000条

#### 清洗规则

1. **过滤低质量对话**：保留用户评分≥3.0、7天内的非测试用户对话
2. **去除重复查询**：基于语义相似度（≥0.95）去重，保留评分最高的对话
3. **标注工具链**：从工具使用字段提取工具链，并对查询进行领域分类
4. **数据验证**：验证对话数据完整性，包括必填字段、工具链、响应长度和评分范围

#### 清洗数据存储

清洗后的数据存储在`training_dataset`表中：
```sql
CREATE TABLE IF NOT EXISTS training_dataset (
    id INT PRIMARY KEY AUTO_INCREMENT,
    conversation_id VARCHAR(50) UNIQUE NOT NULL,  -- 原始对话ID
    user_id INT NOT NULL,
    query TEXT NOT NULL,
    response TEXT NOT NULL,
    tool_chain JSON NOT NULL,  -- ["get_user_profile", "design_program", ...]
    domain VARCHAR(50) NOT NULL,  -- muscle_gain, fat_loss, rehabilitation, nutrition
    reward FLOAT NOT NULL,
    similarity_cluster INT DEFAULT NULL,  -- 相似度聚类ID
    is_validated BOOLEAN DEFAULT FALSE,  -- 是否人工验证过
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_domain (domain),
    INDEX idx_reward (reward),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 微调架构设计

#### 微调触发条件

微调将在以下条件全部满足时触发：
- **高质量对话数**：≥5000条（评分≥4.5）
- **场景覆盖度**：每个场景至少20%
- **Few-Shot命中率**：<60%（表示需要通过微调提高性能）

#### 微调方法：LoRA

LoRA（Low-Rank Adaptation）是一种参数高效的微调方法：

**LoRA参数配置**：
```python
lora_config = LoraConfig(
    r=16,                # Rank（秩）：控制适配器的参数量
    lora_alpha=32,       # Alpha：缩放因子（通常为 r 的 2 倍）
    lora_dropout=0.05,   # Dropout：防止过拟合
    target_modules=[     # 目标模块：对哪些层应用LoRA
        "q_proj",
        "v_proj",
        "k_proj",
        "o_proj",
        "gate_proj",
        "up_proj",
        "down_proj"
    ],
    bias="none",         # 不训练bias
    task_type="CAUSAL_LM"  # 任务类型：因果语言模型
)
```

**LoRA的优势**：
- 参数量小（<1%原模型参数）
- 训练快速（GPU时间减少80%+）
- 部署灵活（可切换适配器）
- 避免灾难性遗忘

#### 部署策略

完整的微调模型部署流程包括：
1. **训练LoRA适配器**：在GPU服务器上训练3-5个epochs
2. **离线验证**：人工评估抽样100条，自动评估工具链准确率
3. **A/B测试**：50%流量到微调模型，50%流量到基线模型，持续7天
4. **灰度发布**：逐步增加流量比例（70%→90%→100%）
5. **全量替换**：更新Ollama模型，保留原模型作为降级方案

#### 风险评估与缓解

主要风险及缓解措施：

| 风险类型 | 缓解措施 |
|---------|---------|
| **数据质量** | 人工抽查100条 + 严格验证规则 |
| **过拟合** | Early stopping + 验证集监控 + Dropout |
| **性能降低** | 模型量化 + 推理优化 + A/B测试 |
| **场景覆盖不足** | 主动生成补充数据 + 迁移学习 |
| **灾难性遗忘** | LoRA方法 + 保留基础任务数据 |
