## 架构概览

DAML-RAG采用**分层架构**，将通用框架组件与特定领域应用逻辑分离：

```
┌─────────────────────────────────────────────────────────────┐
│                      应用层 (Applications)                   │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  Fitness Application (健身领域)                      │  │
│  │  - 23个MCP工具                                       │  │
│  │  - DAG模板系统                                       │  │
│  │  - LLM决策引擎                                       │  │
│  │  - LLM分析引擎                                       │  │
│  │  - 三段式编排器                                      │  │
│  └──────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                            ↓ 依赖
┌─────────────────────────────────────────────────────────────┐
│                    框架层 (Framework)                        │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  通用组件（领域无关）                                 │  │
│  │  - MCP客户端池                                       │  │
│  │  - 编排器基类                                        │  │
│  │  - 三层检索引擎                                      │  │
│  │  - 缓存管理器                                        │  │
│  │  - 元数据存储                                        │  │
│  └──────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

**核心理念**：
- ✅ **框架层**：领域无关，可被多个垂直领域复用
- ✅ **应用层**：特定领域的业务逻辑和工具实现
- ✅ **依赖注入**：框架层通过接口调用应用层，保持解耦

## 集成示例

### 示例1：使用三段式编排器

```python
from applications.fitness.three_stage_orchestrator import (
    ThreeStageOrchestrator,
    ThreeStageRequest
)

# 初始化编排器
orchestrator = ThreeStageOrchestrator()

# 创建请求
request = ThreeStageRequest(
    user_query="我想制定一个增肌训练计划",
    user_id="user_123",
    user_profile={
        "basic_info": {"age": 28, "gender": "男"},
        "fitness_config": {"fitness_level": "intermediate"},
        "fitness_goals": {"primary_goal": "增肌"}
    }
)

# 执行三段式工作流程
result = await orchestrator.execute(request)

# 获取结果
if result.success:
    print(f"模板: {result.dag_selection.selected_template_id}")
    print(f"执行工具: {result.dag_execution.tasks_completed}个")
    print(f"最终响应: {result.final_response}")
```

## 总结

### 框架层优势
- ✅ **可复用**：可被其他垂直领域（医疗、教育等）复用
- ✅ **可扩展**：新增领域只需实现应用层
- ✅ **可维护**：框架层和应用层独立演进

### 应用层优势
- ✅ **领域专注**：专注于健身领域的业务逻辑
- ✅ **灵活定制**：可根据需求定制工具和模板
- ✅ **快速迭代**：不影响框架层的稳定性

### 三段式架构优势
- ✅ **避免幻觉**：LLM不直接调用MCP，不生成虚假数据
- ✅ **保留价值**：程序的DAG编排、三层检索、并行优化仍然有价值
- ✅ **充分利用LLM**：LLM智能选择方案、深度分析结果
- ✅ **灵活扩展**：新增DAG模板无需修改LLM，LLM进步自动提升系统
