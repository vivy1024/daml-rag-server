## 🏗️ 架构层次

```
第1层: api/                     # API接口层（HTTP路由）
         ↓
第2层: applications/           # 应用层（健身领域业务）
         ↓
第3层: framework/              # 框架层（通用技术服务）
         ↓
第4层: shared/                 # 共享层（配置与常量）
```

**基础设施层（framework/infrastructure/）**：
```
framework/infrastructure/
├── retrieval/       # 检索组件（从tools迁移）
├── storage/         # 存储组件（从utils迁移）
├── optimization/    # 优化组件（从utils迁移）
└── reasoning/       # 推理组件（从utils迁移）
```

**设计原则**：
- ✅ **四层清晰**：API层→应用层→框架层→共享层
- ✅ **领域分离**：框架层领域无关，应用层领域专用
- ✅ **薄路由**：API层专注HTTP请求处理
- ✅ **统一基建**：基础设施组件集中管理
- ✅ **分层清晰**：依赖关系明确，职责单一

**模块分类说明**：
- **框架层** (`framework/`)：领域无关，可复用到其他垂直领域（教育、医疗等）
  - 例如：`MCPOrchestrator` - 通用MCP工具编排器
- **应用层** (`applications/`)：领域专用，包含健身领域的特定实现
  - 例如：`FitnessOrchestrator` - 健身编排器（继承MCPOrchestrator）

```bash
# 1. 启动所有Docker服务
cd F:\build_body
docker-compose up -d

# 2. 查看服务状态
docker-compose ps

# 3. 重启DAML-RAG Server
docker-compose restart fitness_daml_rag
```

```bash

# 测试API
```

## 📝 维护指南

### 文档更新规则

- **修改代码后**: 更新 `docs/03-代码参考/` 下的对应文档
- **新增功能**: 在 `docs/` 创建新文档并更新索引
- **版本递增**: 更新版本号和日期
- **Docker服务**: 修改代码后必须重启容器

- **新测试**: 添加到 `tests/` 目录
