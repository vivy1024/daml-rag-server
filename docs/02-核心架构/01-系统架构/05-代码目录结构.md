## 🏗️ 架构层次关系

```
┌─────────────────────────────────────────────────────────────┐
│                      API层 (api/)                           │
│  HTTP路由 → 请求验证 → 调用应用层 → 返回响应                  │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                   应用层 (applications/)                     │
│  领域适配器 → DAG编排 → MCP工具 → 服务组件 → 工作流执行        │
│  （健身领域专用实现）                                         │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                   框架层 (framework/)                        │
│  三层检索 → 技能系统 → 通用编排 → 客户端 → 存储 → 监控         │
│  （领域无关，可复用）                                         │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                     基础设施                                 │
│  Neo4j │ Qdrant │ MySQL │ Redis │ LLM API                   │
└─────────────────────────────────────────────────────────────┘
```

### 设计原则

1. **领域分离**：框架层领域无关，应用层领域专用
2. **依赖倒置**：高层模块不依赖低层模块，都依赖抽象
3. **薄路由**：API层只做路由转发，不包含业务逻辑
4. **可扩展**：通过DomainAdapter接入新的垂直领域
