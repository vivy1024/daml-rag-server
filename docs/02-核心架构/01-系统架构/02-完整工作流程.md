## 🎯 核心理念：LLM选择 + 程序执行 + LLM综合

玉珍健身的新设计哲学：**充分利用LLM能力，同时保证数据安全和程序价值**

### 三段式架构概览

```
用户查询
  ↓
【阶段1：LLM决策】步骤4-6.5
  理解意图 → 选择DAG方案（从预定义模板中选择）
  ↓
【阶段2：程序执行】步骤7-9
  执行DAG → 三层检索 → 并行优化 → 结构化结果
  ↓
【阶段3：LLM综合】步骤10
  基于真实数据 → 专业分析 → 生成建议（不仅是翻译）
```

**核心优势**：
1. **LLM做决策**：理解意图、选择最合适的DAG方案
2. **程序做执行**：保证依赖关系、数据安全、性能优化
3. **LLM做综合**：基于真实数据进行专业分析和建议
4. **避免幻觉**：LLM不直接调用MCP，不生成虚假数据
5. **保留价值**：程序的DAG编排、三层检索、并行优化仍然有价值
6. **灵活扩展**：新增DAG模板无需修改LLM，LLM进步自动提升系统

### 与旧架构的对比

| 方面 | 旧架构（LLM只翻译） | 新架构（三段式） |
|------|-------------------|-----------------|
| **LLM角色** | 仅翻译工具结果 | 决策+综合分析 |
| **意图识别** | 规则匹配（固定） | LLM智能选择 |
| **DAG选择** | 硬编码规则 | LLM从模板中选择 |
| **结果分析** | 简单翻译 | 专业深度分析 |
| **灵活性** | 新意图需改代码 | 新增模板即可 |
| **LLM进步** | 无法自动受益 | 自动提升系统 |

### 步骤5：智能模型选择（三段式决策）⭐

**文件**: `src/chat_service.py`  
**方法**: `_should_use_teacher_model()`

```python
def _should_use_teacher_model(message, context):
    """
    三段式决策：
    1. similarity < 0.5  → 学生模型（Anthropic Claude，免费）
    2. similarity >= 0.7 → 教师模型（DeepSeek，付费）
    3. 0.5 <= similarity < 0.7 → 检查Few-Shot
       - Few-Shot >= 3 → 学生模型
       - Few-Shot < 3  → 教师模型（保险）
    """
    
    is_complex, similarity, reason = self.query_complexity_classifier.classify_complexity(message)
    
    if similarity < 0.5:
        return False  # 学生模型
    elif similarity >= 0.7:
        return True   # 教师模型
    else:
        # 0.5-0.7 灰色地带：检查Few-Shot
        few_shot_count = context.get('few_shot_count', 0)
        return few_shot_count < 3  # 不足3个示例，用教师保险
```

**关键点**：
- ✅ 成本控制：90%请求用学生模型
- ✅ 质量保障：复杂查询自动升级教师模型
- ✅ Few-Shot支撑：充足示例可降级学生模型

> **⚠️ v5.2.0更新**：当`DUAL_MODEL_ENABLED=false`时，此步骤直接选择`teacher`（DeepSeek），不执行模型选择逻辑。服务器环境无Anthropic Claude，所有请求都使用DeepSeek + API池轮询。

## 🎯 三段式架构如何避免幻觉？

### 1. 阶段1（LLM决策）：避免直接调用MCP

**旧方案问题**：
```
用户查询 → LLM直接调用MCP工具 → 可能选错工具或参数
```

**新方案解决**：
```
用户查询 → LLM从预定义DAG模板中选择 → 程序执行模板
```

**关键点**：
- ✅ LLM只选择模板ID，不直接调用MCP
- ✅ 模板定义了完整的工具链和依赖关系
- ✅ 程序保证工具调用的正确性和安全性

### 2. 阶段2（程序执行）：三层检索保证数据真实

```
Layer 1（向量）→ 召回率高（GTE-Large-zh语义检索）
    ↓
Layer 2（图谱）→ 精确度高（Neo4j禁忌动作过滤）
    ↓
Layer 3（规则）→ 个性化（训练水平、器械、恢复能力）
    ↓
最终结果：100%真实、已验证的数据
```

**对比**：
| 方法 | 召回率 | 精度 | 个性化 | 安全性 |
|-----|-------|------|--------|--------|
| **单纯向量** | 90% | 60% | ❌ | ❌ |
| **向量+图谱** | 90% | 85% | ❌ | ✅ |
| **三层检索** | 90% | 95% | ✅ | ✅ |

### 3. 阶段3（LLM综合）：基于真实数据的专业分析

**旧方案限制**：
```
LLM只能翻译 → 能力被严重限制 → 无法充分利用LLM
```

**新方案平衡**：
```
LLM基于真实数据进行专业分析 → 充分利用LLM能力 → 但不能脱离数据幻觉
```

**系统提示词约束**：
```
✅ 允许：专业分析、深度推理、个性化建议
✅ 必须：基于工具结果、提供推理依据
❌ 禁止：推荐禁忌动作、猜测数据、添加虚假信息
```

**结果**：
- ✅ LLM可以进行专业分析（不仅是翻译）
- ✅ 所有建议可追溯到工具结果
- ✅ 禁忌动作绝对不推荐
- ✅ 数据不足时明确告知

## 🎨 LLM响应优化（v5.1.0新增）

### 问题背景

在v5.0.0版本中，虽然实现了三段式架构，但存在一个关键问题：

**用户输入简单问候（如"你好"）时，系统返回完整的训练计划（300字），而不是简短的友好回应。**

**根本原因**：
1. DAG模板系统只定义"做什么"（工具调用），不定义"怎么说"（响应风格）
2. 步骤10的LLM不知道应该简短回答还是详细分析
3. 信息传递链断裂：步骤6.5选择的模板信息没有有效传递到步骤10

### 解决方案：response_hint字段

**核心思路**：为每个DAG模板添加`response_hint`字段，指导步骤10的LLM如何生成回答。

#### 1. 扩展DAGTemplate类

```python
@dataclass
class DAGTemplate:
    # ... 原有字段 ...
    response_hint: str = ""  # LLM响应提示：指导步骤10如何生成回答
```

#### 2. 为所有模板配置response_hint

```python
# greeting模板（新增）
DAGTemplate(
    template_id="greeting",
    name="问候闲聊",
    required_tools=[],  # 不调用任何工具
    response_hint="简短友好，1-2句话，不要提供训练建议"
)

# complete_training_plan模板
DAGTemplate(
    template_id="complete_training_plan",
    name="完整训练计划",
    required_tools=[...],
    response_hint="详细专业，提供完整的训练计划，包含动作选择、组数次数、训练量分配、周期化安排，字数300-500字"
)

# quick_consultation模板
DAGTemplate(
    template_id="quick_consultation",
    name="快速咨询",
    required_tools=["get_user_profile"],
    response_hint="简洁明了，直接回答用户问题，提供实用建议，2-3段话，字数100-200字"
)
```

#### 3. 步骤10动态使用response_hint

```python
# 步骤10：LLM深度分析
template = template_manager.get_template(selected_template_id)
response_hint = template.response_hint

analysis_prompt = f"""
你是玉珍健身专业教练。

{response_hint}

## 用户查询
{message}

## 工具执行结果
{tool_results}

请根据响应要求生成回答。
"""
```
