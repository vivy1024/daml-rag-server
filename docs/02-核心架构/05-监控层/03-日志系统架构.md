## 概述

DAML-RAG的日志系统采用结构化日志设计，提供多层次、可追踪的日志记录能力。系统支持会话级日志追踪、步骤级性能监控、结构化数据检测和完整的错误堆栈记录。

### 设计目标

1. **可追踪性** - 通过request_id关联整个请求生命周期的所有日志
2. **结构化** - 使用结构化格式便于日志分析和查询
3. **持久化** - 日志文件持久化存储，支持历史分析
4. **性能监控** - 记录关键性能指标（TTFB、耗时、吞吐量）
5. **错误诊断** - 完整的错误堆栈和上下文信息
6. **可观测性** - 与Prometheus、Grafana集成实现可视化

## 日志级别定义

### Python标准日志级别

系统使用Python标准logging模块的五个日志级别：

| 级别 | 数值 | 用途 | 示例场景 |
|------|------|------|----------|
| **DEBUG** | 10 | 详细的调试信息 | 变量值、函数调用、数据结构 |
| **INFO** | 20 | 一般信息性消息 | 会话开始/结束、步骤执行、正常流程 |
| **WARNING** | 30 | 警告信息 | 降级策略触发、缓存未命中、重试 |
| **ERROR** | 40 | 错误信息 | 异常捕获、操作失败、数据错误 |
| **CRITICAL** | 50 | 严重错误 | 系统崩溃、服务不可用、数据损坏 |

### 自定义日志级别（DAG可视化器）

DAG可视化器定义了三个自定义日志级别用于控制输出详细程度：

```python
class LogLevel(Enum):
    """日志级别"""
    MINIMAL = 1    # 最小日志（仅失败和完成）
    NORMAL = 2     # 正常日志（所有状态）
    DETAILED = 3   # 详细日志（包含详细信息）
    DEBUG = 4      # 调试日志（包含所有调试信息）
```

## 日志组件架构

### 核心组件

```
日志系统
├─ EnhancedLogger（增强日志记录器）
│   ├─ 会话生命周期管理
│   ├─ 步骤执行追踪
│   ├─ 结构化数据检测
│   ├─ 错误记录和堆栈
│   └─ 性能指标收集
├─ SessionLogContext（会话日志上下文）
│   ├─ 请求元数据
│   ├─ 性能指标
│   ├─ 步骤执行记录
│   ├─ 结构化数据记录
│   └─ 错误记录
└─ Python标准logging模块
    ├─ Logger实例
    ├─ Handler配置
    └─ Formatter配置
```

### EnhancedLogger类

**职责**：提供会话级的结构化日志记录

**核心方法**：

```python
class EnhancedLogger:
    def log_session_start(request_id, user_id, session_id, query, domain)
        """记录流式会话开始"""
    
    def log_step_start(request_id, step_number, step_name, metadata)
        """记录步骤开始"""
    
    def log_step_complete(request_id, step_number, success, result_summary, metadata)
        """记录步骤完成"""
    
    def log_structured_data_detected(request_id, data_type, data_size, marker, extraction_success)
        """记录结构化数据检测"""
    
    def log_error(request_id, error, context_info, step_number)
        """记录错误（包含完整堆栈和上下文）"""
    
    def log_session_complete(request_id, tokens_generated, content_length, ttfb_ms, generation_speed)
        """记录会话完成"""
    
    def get_session_summary(request_id)
        """获取会话摘要"""
```

### SessionLogContext类

**职责**：存储单个会话的所有日志信息

**数据结构**：

```python
@dataclass
class SessionLogContext:
    # 请求元数据
    request_id: str
    user_id: str
    session_id: str
    query: str
    query_length: int
    domain: str
    start_time: float
    timestamp: str
    
    # 性能指标
    ttfb_ms: Optional[float]
    total_duration_ms: Optional[float]
    tokens_generated: int
    content_length: int
    
    # 步骤执行记录
    steps_executed: List[Dict[str, Any]]
    
    # 结构化数据检测
    structured_data_detected: List[Dict[str, Any]]
    
    # 错误记录
    errors: List[Dict[str, Any]]
    
    # 成功标志
    success: bool
```

## 日志记录流程

### 会话生命周期日志

```
1. 会话开始
   ↓
   log_session_start()
   - 创建SessionLogContext
   - 记录请求元数据
   - 记录开始时间
   
2. 步骤执行
   ↓
   log_step_start() → 执行步骤 → log_step_complete()
   - 记录步骤开始时间
   - 记录步骤元数据
   - 计算步骤耗时
   - 记录执行结果
   
3. 结构化数据检测（可选）
   ↓
   log_structured_data_detected()
   - 记录数据类型
   - 记录数据大小
   - 记录提取状态
   
4. 错误处理（如果发生）
   ↓
   log_error()
   - 记录错误类型
   - 记录错误消息
   - 记录完整堆栈
   - 记录上下文信息
   
5. 会话完成
   ↓
   log_session_complete()
   - 计算总耗时
   - 记录性能指标
   - 统计步骤信息
   - 生成会话摘要
   - 清理会话上下文
```

## 日志存储策略

### 文件存储

**日志文件位置**：
```
容器内路径:
/app/logs/
├─ daml-rag-20251223.log          # 今天的所有日志
├─ daml-rag-error-20251223.log    # 今天的错误日志
├─ daml-rag-20251222.log          # 昨天的所有日志
├─ daml-rag-error-20251222.log    # 昨天的错误日志
└─ ...

本地映射路径:
F:\build_body\data\logs\
├─ daml-rag-20251223.log
├─ daml-rag-error-20251223.log
└─ ...
```

**日志文件命名规则**：
- 格式：`daml-rag-YYYYMMDD.log`
- 按日期自动创建新文件
- 便于按日期查找和管理

### 文件轮转策略

**轮转配置**：
- **轮转大小**: 50MB（所有日志）/ 10MB（错误日志）
- **保留数量**: 10个文件（所有日志）/ 5个文件（错误日志）
- **保留期限**: 建议30天（通过定期清理脚本）
- **编码**: UTF-8（支持中文日志）

**实现方式**：
```python
from logging.handlers import RotatingFileHandler
from pathlib import Path
from datetime import datetime

# 日志目录
LOG_DIR = Path('/app/logs')
LOG_DIR.mkdir(parents=True, exist_ok=True)

# 日志文件路径（按日期命名）
LOG_FILE = LOG_DIR / f'daml-rag-{datetime.now().strftime("%Y%m%d")}.log'
ERROR_LOG_FILE = LOG_DIR / f'daml-rag-error-{datetime.now().strftime("%Y%m%d")}.log'

# 所有日志处理器
file_handler = RotatingFileHandler(
    LOG_FILE,
    maxBytes=50 * 1024 * 1024,  # 50MB
    backupCount=10,
    encoding='utf-8'
)
file_handler.setLevel(logging.INFO)

# 错误日志处理器
error_handler = RotatingFileHandler(
    ERROR_LOG_FILE,
    maxBytes=10 * 1024 * 1024,  # 10MB
    backupCount=5,
    encoding='utf-8'
)
error_handler.setLevel(logging.ERROR)
```

## 日志最佳实践

### 1. 使用结构化日志

**推荐**：
```python
logger.info(
    f"[{request_id}] 步骤完成: "
    f"step={step_number}, "
    f"duration={duration_ms:.2f}ms, "
    f"success={success}"
)
```

**不推荐**：
```python
logger.info(f"步骤{step_number}完成，耗时{duration_ms}ms")
```

### 2. 包含关键上下文

**必须包含**：
- request_id：用于追踪整个请求
- user_id：用于用户行为分析
- session_id：用于会话追踪
- timestamp：精确的时间戳

### 3. 记录性能指标

**关键指标**：
- TTFB（首字节响应时间）
- 总耗时
- 步骤耗时
- 生成速度（tokens/s）
- 数据大小

### 4. 完整的错误信息

**错误日志应包含**：
- 错误类型
- 错误消息
- 完整堆栈
- 上下文信息（请求参数、状态等）
- 发生步骤

### 5. 避免敏感信息

**禁止记录**：
- 用户密码
- API密钥
- 个人隐私信息（身份证、手机号等）

**脱敏处理**：
```python
# 脱敏用户查询（如果包含敏感信息）
safe_query = query[:100] + '...' if len(query) > 100 else query
logger.info(f"query='{safe_query}'")
```

### 6. 合理的日志级别

**级别选择**：
- DEBUG：仅在开发环境使用，记录详细调试信息
- INFO：正常流程、关键操作、性能指标
- WARNING：降级策略、重试、非致命错误
- ERROR：异常、失败操作、数据错误
- CRITICAL：系统崩溃、服务不可用

### 7. 性能考虑

**优化建议**：
- 避免在循环中记录大量日志
- 使用异步日志处理（如果需要）
- 定期清理旧日志文件
- 使用日志采样（高频操作）

## 故障排查

### 常见问题

**1. 日志文件过大**
- 检查轮转配置是否生效
- 检查是否有大量DEBUG日志
- 调整日志级别为INFO

**2. 日志丢失**
- 检查磁盘空间
- 检查文件权限
- 检查日志Handler配置

**3. 性能影响**
- 减少日志输出频率
- 使用异步日志
- 调整日志级别

**4. 日志格式不一致**
- 统一使用EnhancedLogger
- 遵循日志格式规范
- 使用结构化日志
