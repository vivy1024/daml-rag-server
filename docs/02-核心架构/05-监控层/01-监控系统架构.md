## 概述

DAML-RAG框架的监控系统已完成简化，从13个文件（244KB）精简到5个核心模块（72KB），减少70%代码量。简化后的监控系统专注于通过API接口提供监控数据，删除了所有未使用的独立部署、可视化和告警功能。

### 简化原则

**核心思想**：监控层的唯一职责是通过API接口提供监控数据

- ✅ **支持健康检查API**：`/api/health` 系列接口
- ✅ **支持性能指标API**：系统和应用指标收集
- ✅ **支持流式监控API**：流式会话性能监控
- ✅ **支持Prometheus导出**：时序数据查询
- ✅ **提供并发控制**：防止服务器过载
- ❌ **不负责独立部署**：监控通过API提供
- ❌ **不负责可视化**：由前端负责
- ❌ **不负责告警**：未使用的功能

### 简化成果

| 指标 | 简化前 | 简化后 | 改进 |
|------|--------|--------|------|
| 文件数量 | 13个 | 5个 | 减少62% |
| 代码大小 | 244KB | 72KB | 减少70% |
| API功能 | 100% | 100% | 零损失 |
| 前端监控 | 100% | 100% | 零损失 |
| Dashboard | 100% | 100% | 零损失 |
| 并发控制 | ✅ | ✅ | 保留 |
| 性能 | 基准 | 略有提升 | 优化 |

### 架构说明

**5个核心模块**：
1. **StreamingMetrics**：流式会话性能监控
2. **MetricsCollector**：系统和应用指标收集
3. **ConcurrencyLimiter**：API并发控制和过载保护
4. **StructuredLogger**：统一的结构化日志记录
5. **PrometheusIntegration**：Prometheus格式指标导出

**删除的8个模块**：
- ❌ performance_monitor.py（68KB）- 过度设计

- ❌ workflow_metrics.py（11KB）- 未使用

## 核心模块详解

### 1. StreamingMetrics - 流式会话监控（21KB）

**职责**：记录和统计流式会话的性能指标

**核心功能**：
- 记录每个流式会话的TTFB、总耗时、令牌生成速度
- 提供时间窗口内的统计数据
- 支持 `/api/health/metrics/streaming` 端点
- 线程安全的活跃连接数跟踪

**接口**：
```python
class StreamingMonitor:
    def record_session(
        self,
        session_id: str,
        ttfb_ms: float,
        duration_ms: float,
        tokens: int,
        success: bool
    ) -> None
    
    def get_statistics(
        self,
        time_window_seconds: int = 3600
    ) -> Dict[str, Any]
    
    def get_recent_metrics(
        self,
        limit: int = 100
    ) -> List[Dict[str, Any]]
```

**保留原因**：
- 前端监控页面直接使用
- 提供流式会话性能分析
- 无替代方案

**Prometheus指标**：
```python
# TTFB直方图
streaming_ttfb = Histogram(
    'streaming_session_ttfb_seconds',
    'Time to first byte for streaming sessions',
    buckets=[0.1, 0.5, 1.0, 2.0, 5.0, 10.0, 20.0]
)

# 会话持续时间
streaming_duration = Histogram(
    'streaming_session_duration_seconds',
    'Total duration of streaming sessions',
    buckets=[1, 5, 10, 30, 60, 120, 180, 300]
)

# 令牌生成速率
streaming_tokens_rate = Histogram(
    'streaming_session_tokens_per_second',
    'Token generation rate for streaming sessions',
    buckets=[1, 5, 10, 20, 50, 100, 200]
)
```

### 2. MetricsCollector - 指标收集器（18KB）

**职责**：收集和管理系统性能指标

**核心功能**：
- 收集CPU、内存、磁盘使用率
- 收集请求耗时、错误率等应用指标
- 支持 `/api/health/metrics` 端点
- 导出Prometheus格式指标

**接口**：
```python
class MetricsCollector:
    def get_metric(self, name: str) -> Metric
    
    def get_all_metrics(self) -> Dict[str, Metric]
    
    def export_prometheus(self) -> str
    
    def record_request(
        self,
        endpoint: str,
        method: str,
        status: int,
        duration: float
    ) -> None
```

**保留原因**：
- 前端监控页面使用
- 支持Prometheus导出
- 核心指标收集功能

**指标类型**：
- **系统指标**：CPU、内存、磁盘使用率
- **进程指标**：进程CPU、内存、线程数
- **应用指标**：请求数、错误率、响应时间

---

### 3. ConcurrencyLimiter - 并发限制器（13KB）

**职责**：提供API并发控制，防止服务器过载

**核心功能**：
- 限制同时处理的请求数量
- 支持用户分级（VIP优先）
- 提供优雅降级（429错误）
- 队列管理和超时控制

**接口**：
```python
class ConcurrencyLimiter:
    async def acquire(
        self,
        user_id: str,
        session_id: str,
        timeout: float = 30.0
    ) -> bool
    
    async def release(
        self,
        session_id: str
    ) -> None
    
    def get_stats(self) -> Dict[str, Any]

# 全局实例
concurrency_limiter = ConcurrencyLimiter(
    max_concurrent=100,
    max_queue_size=200
)
```

**保留原因**：
- 被核心API路由直接使用（`/api/chat`, `/api/chat/stream`）
- 提供生产环境必需的并发控制
- 防止服务器过载和资源耗尽
- 与其他性能组件深度集成
- 有完整的测试覆盖

**使用位置**：
- `src/api/routes/chat.py` - 两个核心API端点
- `src/applications/fitness/workflow/singletons.py` - 单例管理

### 4. StructuredLogger - 结构化日志器（8KB）

**职责**：提供结构化日志记录功能

**核心功能**：
- 结构化日志格式（JSON）
- 支持trace_id追踪
- 日志级别过滤
- 性能日志记录

**接口**：
```python
class StructuredLogger:
    def info(self, message: str, **kwargs) -> None
    
    def error(self, message: str, **kwargs) -> None
    
    def warning(self, message: str, **kwargs) -> None
    
    def debug(self, message: str, **kwargs) -> None

def get_logger(name: str) -> StructuredLogger

def set_trace_id(trace_id: str) -> None
```

**保留原因**：
- health API使用
- 提供统一的日志格式
- 支持分布式追踪

**日志格式**：
```json
{
  "timestamp": "2026-01-10T10:30:45.123Z",
  "level": "INFO",
  "logger": "api.health",
  "message": "Health check completed",
  "trace_id": "abc123",
  "duration_ms": 125.5,
  "extra": {
    "status": "healthy",
    "components": 5
  }
}
```

### 5. PrometheusIntegration - Prometheus集成（11KB）

**职责**：提供Prometheus格式的指标导出

**核心功能**：
- 注册Prometheus指标
- 导出Prometheus文本格式
- 支持 `/api/health/metrics/prometheus` 端点

**接口**：
```python
def register_prometheus_metrics() -> None

def export_prometheus_metrics() -> str

def increment_counter(
    name: str,
    labels: Dict[str, str] = None
) -> None

def observe_histogram(
    name: str,
    value: float,
    labels: Dict[str, str] = None
) -> None
```

**保留原因**：
- PHP后端通过此端点获取指标
- 前端Dashboard页面需要时序数据
- Prometheus服务独立部署到后端

**导出格式示例**：

streaming_session_ttfb_seconds_bucket{le="1.0"} 82
streaming_session_ttfb_seconds_sum 72.5

## 监控API端点

### 健康检查API

所有监控API端点位于 `src/api/routes/health.py`：

| 端点 | 功能 | 使用模块 | 前端使用 |
|------|------|---------|---------|
| `GET /api/health` | 综合健康检查 | MetricsCollector | ✅ ai-monitor.vue |
| `GET /api/health/components` | 组件详细状态 | MetricsCollector | ❌ 管理功能 |
| `GET /api/health/metrics` | 系统性能指标 | MetricsCollector | ✅ ai-monitor.vue |
| `GET /api/health/metrics/prometheus` | Prometheus格式指标 | PrometheusIntegration | ✅ Dashboard页面（间接） |
| `GET /api/health/metrics/streaming` | 流式输出监控 | StreamingMetrics | ✅ ai-monitor.vue |
| `GET /api/health/metrics/streaming/recent` | 最近流式会话 | StreamingMetrics | ❌ 管理功能 |

### 前端集成

**监控页面**（`yuzhen_fitness/src/views/admin/ai-monitor.vue`）：
- 调用 `/api/health` 获取系统状态
- 调用 `/api/health/metrics` 获取性能指标
- 调用 `/api/health/metrics/streaming` 获取流式统计

**Dashboard页面**（`yuzhen_fitness/src/views/admin/dashboards/*.vue`）：
- 通过PHP后端 `/admin/metrics/prometheus/raw` 获取Prometheus数据
- PHP后端调用 `/api/health/metrics/prometheus` 获取指标
- 前端使用Chart.js渲染时序图表

## 最佳实践

### 1. 监控粒度

✅ **API级别**：监控所有健康检查API的响应时间和成功率  
✅ **流式会话级别**：监控TTFB、持续时间、令牌生成速率  
✅ **系统级别**：监控CPU、内存、磁盘使用率  
✅ **并发级别**：监控活跃连接数、队列长度、拒绝率
