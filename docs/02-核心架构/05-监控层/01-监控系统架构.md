## 概述

DAML-RAG框架的监控系统提供全面的性能跟踪、分析和告警功能，确保系统的可观测性和可维护性。监控系统包含三个核心组件：
1. **DAMLWorkflowMonitor** - 工作流程级别的全链路监控
2. **PerformanceMonitor** - 细粒度的性能监控和Prometheus集成
3. **StreamingMetrics** - 流式会话监控指标和实时性能分析

### 设计理念

**核心思想**：全链路可观测，实时性能分析

- ✅ **11步工作流程全链路跟踪**：从用户档案加载到交互记录的完整监控
- ✅ **三层检索详细监控**：Vector→Graph→Rules每层的性能和效果
- ✅ **实时性能统计**：实时计算成功率、耗时、缓存命中率等指标
- ✅ **性能瓶颈识别**：自动检测超过阈值的慢步骤
- ✅ **Prometheus集成**：标准化的指标导出，支持Grafana可视化

### 架构优势

1. **完整性**：覆盖工作流程的每个步骤和检索层级
2. **实时性**：实时统计和告警，快速发现问题
3. **可追溯性**：每个会话都有完整的执行记录
4. **标准化**：Prometheus格式导出，易于集成
5. **低开销**：异步记录，对性能影响小

## DAMLWorkflowMonitor - 工作流程监控器

### 核心功能

1. **11步工作流程全链路跟踪**
2. **三层检索详细监控**
3. **实时性能统计**
4. **成本效益分析**
5. **性能瓶颈识别**
6. **历史趋势分析**

### 数据模型

**WorkflowSession（工作流程会话）**：
```python
@dataclass
class WorkflowSession:
    session_id: str                                    # 会话ID
    user_id: Optional[str]                             # 用户ID
    query: str                                         # 查询文本
    start_time: datetime                               # 开始时间
    end_time: Optional[datetime]                       # 结束时间
    total_duration_ms: Optional[float]                 # 总耗时
    steps: Dict[WorkflowStep, StepMetrics]             # 步骤指标
    retrieval_layers: Dict[RetrievalLayer, LayerMetrics]  # 检索层级指标
    final_success: bool                                # 最终成功状态
    error_message: Optional[str]                       # 错误信息
    cost_estimate: float                               # 成本估算
    model_used: str                                    # 使用的模型
    quality_score: Optional[float]                     # 质量评分
    metadata: Dict[str, Any]                           # 元数据
```

**StepMetrics（步骤指标）**：
```python
@dataclass
class StepMetrics:
    step_name: str                    # 步骤名称
    start_time: datetime              # 开始时间
    end_time: Optional[datetime]      # 结束时间
    duration_ms: Optional[float]      # 耗时（毫秒）
    success: bool                     # 是否成功
    error_message: Optional[str]      # 错误信息
    input_size: int                   # 输入大小
    output_size: int                  # 输出大小
    cache_hit: bool                   # 是否缓存命中
    metadata: Dict[str, Any]          # 元数据
```

**LayerMetrics（检索层级指标）**：
```python
@dataclass
class LayerMetrics:
    layer_name: RetrievalLayer        # 层级名称
    step_metrics: StepMetrics         # 步骤指标
    candidates_in: int                # 输入候选数量
    candidates_out: int               # 输出候选数量
    confidence_score: float           # 置信度
    filter_reason: str                # 过滤原因
```

### 工作流程步骤枚举

```python
class WorkflowStep(Enum):
    USER_PROFILE_LOADING = "user_profile_loading"                    # 步骤1
    SESSION_STORAGE = "session_storage"                              # 步骤2
    MEMBERSHIP_CHECK = "membership_check"                            # 步骤3
    BGE_COMPLEXITY_CLASSIFICATION = "bge_complexity_classification"  # 步骤4
    MODEL_SELECTION = "model_selection"                              # 步骤5
    FEW_SHOT_RETRIEVAL = "few_shot_retrieval"                        # 步骤6
    DAG_ORCHESTRATION = "dag_orchestration"                          # 步骤7
    THREE_LAYER_RETRIEVAL = "three_layer_retrieval"                  # 步骤8
    TOOL_RESULT_AGGREGATION = "tool_result_aggregation"              # 步骤9
    LLM_GENERATION = "llm_generation"                                # 步骤10
    INTERACTION_RECORDING = "interaction_recording"                  # 步骤11
```

### 检索层级枚举

```python
class RetrievalLayer(Enum):
    LAYER1_VECTOR = "layer1_vector"      # 向量检索层
    LAYER2_GRAPH = "layer2_graph"        # 图检索层
    LAYER3_RULES = "layer3_rules"        # 规则约束层
```

### 使用示例

```python
# 初始化监控器
monitor = DAMLWorkflowMonitor(
    max_sessions=1000,
    aggregation_window_minutes=60
)

# 开始会话
session_id = monitor.start_session(
    user_id="user_123",
    query="我想制定一个增肌训练计划"
)

# 开始步骤
monitor.start_step(session_id, WorkflowStep.USER_PROFILE_LOADING)

# 完成步骤
monitor.finish_step(
    session_id,
    WorkflowStep.USER_PROFILE_LOADING,
    success=True,
    input_size=100,
    output_size=500,
    cache_hit=True
)

# 开始检索层级
monitor.start_retrieval_layer(session_id, RetrievalLayer.LAYER1_VECTOR)

# 完成检索层级
monitor.finish_retrieval_layer(
    session_id,
    RetrievalLayer.LAYER1_VECTOR,
    success=True,
    candidates_in=100,
    candidates_out=20,
    confidence_score=0.85
)

# 完成会话
monitor.finish_session(
    session_id,
    success=True,
    cost_estimate=0.0025,
    model_used="deepseek-chat",
    quality_score=0.90
)

# 获取性能摘要
summary = monitor.get_performance_summary(time_window_minutes=60)
```

## PerformanceMonitor - 性能监控器

### 核心功能

1. **工作流级别的性能监控**
2. **步骤级别的性能记录**
3. **性能瓶颈检测（阈值1000ms）**
4. **Prometheus指标导出**
5. **DAG执行性能监控**
6. **LLM调用统计**
7. **缓存命中率统计**
8. **工具执行时间分析**
9. **性能趋势分析**

### 数据模型

**WorkflowContext（工作流上下文）**：
```python
@dataclass
class WorkflowContext:
    request_id: str                    # 请求ID
    user_id: str                       # 用户ID
    start_time: float                  # 开始时间
    steps: List[StepRecord]            # 步骤记录列表
    metadata: Dict[str, Any]           # 元数据
```

**PerformanceBottleneck（性能瓶颈）**：
```python
@dataclass
class PerformanceBottleneck:
    request_id: str                    # 请求ID
    step_number: int                   # 步骤编号
    step_name: str                     # 步骤名称
    duration_ms: float                 # 耗时（毫秒）
    threshold_ms: float                # 阈值（毫秒）
    timestamp: float                   # 时间戳
    metadata: Dict[str, Any]           # 元数据
```

**ToolExecutionMetrics（工具执行指标）**：
```python
@dataclass
class ToolExecutionMetrics:

    end_time: float                    # 结束时间

    cache_hit: bool                    # 是否缓存命中
    retry_count: int                   # 重试次数
```

**DAGExecutionMetrics（DAG执行指标）**：

### 使用示例

```python
# 初始化监控器
monitor = PerformanceMonitor(
    max_history_size=1000,
    bottleneck_threshold_ms=1000.0
)

# 开始工作流
context = monitor.start_workflow(
    request_id="req_123",
    user_id="user_456"
)

# 记录步骤
monitor.record_step(
    context=context,
    step_number=1,
    step_name="预加载用户档案",
    duration_ms=120.5,
    success=True,
    metadata={"cache_hit": True}
)

# 完成工作流
monitor.finish_workflow(
    context=context,
    success=True,
    total_duration_ms=2850.5
)

# 使用上下文管理器测量操作
with monitor.measure("database_query"):
    result = await db.query(...)

# 记录工具执行
monitor.record_tool_execution(ToolExecutionMetrics(
    tool_name="intelligent_exercise_selector",
    execution_id="exec_789",
    user_id="user_456",
    start_time=time.time(),
    end_time=time.time() + 2.5,
    duration=2.5,
    success=True,
    cache_hit=False,
    retry_count=0
))

# 导出Prometheus指标
prometheus_metrics = monitor.export_metrics(format="prometheus")

# 获取性能瓶颈
bottlenecks = monitor.get_bottlenecks(
    threshold_ms=1000.0,
    time_window_seconds=3600
)
```

9. **最近会话查询**


## 性能瓶颈检测

### 检测机制

**阈值配置**：
```python
alert_thresholds = {
    "max_total_duration_ms": 5000,      # 总耗时阈值
    "max_single_step_duration_ms": 2000,  # 单步耗时阈值
    "min_success_rate": 0.9,            # 最低成功率
    "max_error_rate": 0.1               # 最高错误率
}
```

**自动检测**：
- 每个步骤完成后自动检查耗时
- 超过阈值自动记录为性能瓶颈
- 实时告警日志输出

**瓶颈分析**：
```python
# 获取性能瓶颈
bottlenecks = monitor.get_bottlenecks(
```

## 告警机制

### 告警类型

1. **慢工作流告警**：总耗时超过阈值
2. **慢步骤告警**：单步耗时超过阈值
3. **低成功率告警**：成功率低于阈值
4. **高错误率告警**：错误率高于阈值

## 最佳实践

### 1. 监控粒度

✅ **工作流级别**：监控整体性能和成功率  
✅ **步骤级别**：监控每个步骤的耗时和成功率  
✅ **检索层级**：监控每层的候选数量和置信度  
✅ **工具级别**：监控每个工具的执行情况  
✅ **LLM级别**：监控LLM调用的耗时和token消耗

### 2. 性能基准

✅ **目标总耗时**：3000ms  
✅ **目标层级耗时**：500ms  
✅ **目标步骤耗时**：1000ms  
✅ **目标成功率**：95%  
✅ **目标缓存命中率**：80%

### 3. 告警配置

✅ **合理阈值**：根据实际情况调整阈值  
✅ **分级告警**：warning和critical两级  
✅ **告警聚合**：避免告警风暴  
✅ **告警通知**：集成到Slack/钉钉等

### 4. 数据保留

✅ **实时数据**：保留最近1000条记录  
✅ **聚合数据**：按小时/天聚合  
✅ **历史数据**：导出到时序数据库  
✅ **定期清理**：避免内存溢出
