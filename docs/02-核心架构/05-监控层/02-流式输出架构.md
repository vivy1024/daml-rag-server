## 概述

流式输出（Server-Sent Events, SSE）是DAML-RAG框架提供实时响应的核心机制，允许服务器向客户端推送实时数据流，实现渐进式内容展示和实时进度反馈。

### 设计理念

**核心思想**：实时反馈，渐进式展示

- ✅ **实时进度反馈**：每个步骤完成后立即推送进度
- ✅ **渐进式内容展示**：LLM生成的内容逐字推送
- ✅ **错误实时通知**：错误发生时立即通知客户端
- ✅ **性能监控集成**：实时推送性能指标
- ✅ **优化TTFB**：首字节时间优化，提升用户体验

### 架构优势

1. **用户体验**：实时反馈，减少等待焦虑
2. **可观测性**：实时了解工作流程执行状态
3. **错误处理**：及时发现和处理错误
4. **性能优化**：TTFB优化，首屏加载快
5. **标准化**：基于SSE标准，易于集成

## SSE事件类型

### 1. progress - 进度事件

**用途**：推送工作流程执行进度

**数据格式**：
```json
{
  "step": 1,
  "step_name": "预加载用户档案",
  "status": "completed",
  "duration_ms": 120.5,
  "message": "用户档案已加载"
}
```

### 2. content - 内容事件

**用途**：推送LLM生成的内容（逐字推送）

**数据格式**：
```json
{
  "content": "根据您的",
  "is_final": false
}
```

### 3. error - 错误事件

**用途**：推送错误信息

**数据格式**：
```json
{
  "error": "工具调用失败",
  "step": 7,
  "details": "intelligent_exercise_selector timeout"
}
```

### 4. metrics - 性能指标事件

**用途**：推送性能监控数据

**数据格式**：
```json
{
  "total_duration_ms": 2850.5,
  "steps_completed": 11,
  "cache_hit_rate": 0.85,
  "success_rate": 1.0
}
```

### 5. done - 完成事件

**用途**：标记流式输出结束

**数据格式**：
```json
{
  "success": true,
  "total_duration_ms": 2850.5,
  "final_message": "工作流程执行完成"
}
```

## 实现架构

### 服务端实现（FastAPI）

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import asyncio
import json

app = FastAPI()

async def generate_sse_stream(query: str, user_id: str):
    """生成SSE流"""
    
    # 步骤1：推送进度
    yield f"event: progress\ndata: {json.dumps({
        'step': 1,
        'step_name': '预加载用户档案',
        'status': 'running'
    })}\n\n"
    
    # 执行步骤1
    await execute_step_1()
    
    # 步骤1完成
    yield f"event: progress\ndata: {json.dumps({
        'step': 1,
        'step_name': '预加载用户档案',
        'status': 'completed',
        'duration_ms': 120.5
    })}\n\n"
    
    # ... 其他步骤
    
    # 步骤10：LLM生成（逐字推送）
    async for chunk in llm_generate_stream(prompt):
        yield f"event: content\ndata: {json.dumps({
            'content': chunk,
            'is_final': False
        })}\n\n"
    
    # 最终完成
    yield f"event: done\ndata: {json.dumps({
        'success': True,
        'total_duration_ms': 2850.5
    })}\n\n"

@app.post("/api/chat/stream")
async def chat_stream(request: ChatRequest):
    """流式聊天接口"""
    return StreamingResponse(
        generate_sse_stream(request.query, request.user_id),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no"  # 禁用Nginx缓冲
        }
    )
```

### 客户端实现（JavaScript）

```javascript
// 创建EventSource连接
const eventSource = new EventSource('/api/chat/stream', {
  method: 'POST',
  body: JSON.stringify({
    query: '我想制定一个增肌训练计划',
    user_id: 'user_123'
  })
});

// 监听进度事件
eventSource.addEventListener('progress', (event) => {
  const data = JSON.parse(event.data);
  console.log(`步骤${data.step}: ${data.step_name} - ${data.status}`);
  updateProgressBar(data.step, 11);
});

// 监听内容事件
eventSource.addEventListener('content', (event) => {
  const data = JSON.parse(event.data);
  appendContent(data.content);
});

// 监听错误事件
eventSource.addEventListener('error', (event) => {
  const data = JSON.parse(event.data);
  showError(data.error);
});

// 监听完成事件
eventSource.addEventListener('done', (event) => {
  const data = JSON.parse(event.data);
  console.log('完成！总耗时:', data.total_duration_ms);
  eventSource.close();
});
```

## 性能优化

### 1. TTFB优化

**策略**：
- 步骤1-2并行执行，快速返回首个进度事件
- 缓存用户档案，减少数据库查询
- 异步执行，避免阻塞

**效果**：
- TTFB < 200ms
- 用户感知延迟降低

### 2. 流式监控集成

**策略**：
- 每个步骤完成后推送进度
- 实时推送性能指标
- 错误立即通知

**效果**：
- 实时可观测性
- 快速错误定位

### 3. 连接管理

**策略**：
- 设置合理的超时时间
- 自动重连机制
- 心跳保活

**效果**：
- 连接稳定性提升
- 减少连接中断

## 错误处理

### 错误类型

1. **连接错误**：网络中断、超时
2. **执行错误**：工具调用失败、LLM调用失败
3. **数据错误**：数据格式错误、解析失败

### 错误处理策略

**服务端**：
```python
try:
    # 执行步骤
    result = await execute_step()
except Exception as e:
    # 推送错误事件
    yield f"event: error\ndata: {json.dumps({
        'error': str(e),
        'step': current_step,
        'details': traceback.format_exc()
    })}\n\n"
    
    # 推送完成事件（失败）
    yield f"event: done\ndata: {json.dumps({
        'success': False,
        'error': str(e)
    })}\n\n"
```

**客户端**：
```javascript
eventSource.addEventListener('error', (event) => {
  const data = JSON.parse(event.data);
  
  // 显示错误信息
  showError(`步骤${data.step}失败: ${data.error}`);
  
  // 关闭连接
  eventSource.close();
  
  // 可选：自动重试
  setTimeout(() => {
    retryRequest();
  }, 3000);
});
```

## 最佳实践

### 1. 事件设计

✅ **事件类型明确**：progress、content、error、metrics、done  
✅ **数据格式统一**：JSON格式，字段命名一致  
✅ **事件顺序保证**：按执行顺序推送  
✅ **错误处理完善**：所有错误都推送error事件

### 2. 性能优化

✅ **TTFB优化**：并行执行，快速返回首个事件  
✅ **流式推送**：LLM内容逐字推送  
✅ **缓存利用**：缓存用户档案等数据  
✅ **连接复用**：保持连接，减少握手开销

### 3. 错误处理

✅ **错误分类**：连接错误、执行错误、数据错误  
✅ **错误通知**：立即推送error事件  
✅ **降级策略**：部分失败时继续执行  
✅ **自动重试**：客户端自动重连

### 4. 监控告警

✅ **TTFB监控**：监控首字节时间  
✅ **成功率监控**：监控流式输出成功率  
✅ **连接监控**：监控连接数和错误率
